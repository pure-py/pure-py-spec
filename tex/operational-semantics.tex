\section{Operational semantics}
\label{sec:opsem}

Values, environments, and evaluation results are given in \figref{values}. For a statement $s$, the result
$\assigns{\rho}$ represents \emph{normal completion} of $s$, with accumulated environment $\rho$; the result
$\returns{v}$ represents \emph{abrupt completion} of $s$ with return value $v$.
Composing statements sequentially composes their results according to the following partial monoid, analogous
to sequential composition of result types:
{\small
\begin{align*}
\assigns{\rho} \override \assigns{\rho'} & = \assigns{(\rho \override \rho')} \\
\assigns{\rho} \override \returns{v} & = \returns{v}
\end{align*}}

with $\assigns{\varnothing}$ as left and right unit.

A value is well-formed at a context entry (\figref{well-formed-env}): ordinary values at
$\statusDefAssigned$, module references and class entries at the corresponding entry. An environment is
well-formed at a context that binds its variables at corresponding entries.

\input{fig/well-formed-env}

Module and program evaluation are given in \figref{eval-modules}; import evaluation in \figref{eval-import-prefix}; importing names from a loaded module in
\figref{eval-imports}. Extend (Definition~\ref{def:extend}) extends to module values by reading its equations with a loaded reference $\modLoaded{q}{\rho}$ carrying an environment in place of a context. The loading judgement $q \Rightarrow_{\mathsf{load}} \rho$ evaluates the import prefix
of $q$ and then its statements, mirroring the well-formedness judgement $\vdash_{\mathsf{load}} q : \Gamma$
(\figref{well-formed-module}); as with the static rules, the mutual
recursion between loading and evaluation is grounded by program well-formedness, which rules out
import cycles (\secref{modules-programs}).
Loading takes a single module; the ancestors of an imported module are loaded by the
loads-as judgement for an import, and directly as premises of \ruleName{eval-from-import} for a
from-import.

The correspondence is exact: if $\vdash_{\mathsf{load}} q : \Gamma$ and $q \Rightarrow_{\mathsf{load}} \rho$ then $\vdash \rho : \Gamma$ (\figref{well-formed-env}). Since
imports precede statements, every module a statement can reference is loaded before the statement runs, and
since loading has no observable effects, reloading a module is unobservable; the semantics therefore needs no
cache of loaded modules. These rules use the environment $\rho_{\pymath{builtins}}$ binding the names of
\figref{predefined}. A program evaluates to its exit status: a run whose main module loads
successfully yields $0$ (rule \ruleName{eval-program}).

\input{fig/eval-modules}

Block evaluation $\rho, b \Rightarrow r$ is given in \figref{eval}. Function definitions delimit the scope of
sequential-composition effects, so as black boxes functions are always pure.

\input{fig/eval}

Expression evaluation $\rho, e \Rightarrow v$ is given in \figref{eval-expr}. The strict operators are given by partial metafunctions $\hat{\odot}$ and
$\hat{\ominus}$, which have the meanings they have in Python. Where one of these is undefined, as
for division by zero or a subscript out of range, the expression has no derivation. The operators
\pyinline{and} and \pyinline{or} evaluate their second operand only when the first leaves the result open, and
a conditional expression requires its condition to be \pyinline{True} or \pyinline{False}, as
\ruleName{eval-if} does. A comprehension evaluates its body once for each binding its qualifiers produce, and
concatenates the results; a generator draws from a list or a tuple, since \PurePy has no wider
notion of iteration.
The pattern-matching judgement $\rho, p, v \matches \rho'$ (\figref{match}) is a deterministic partial
function; we write $\rho, p, v \notmatches$ (with no right-hand side) for $\nexists \rho'.\, \rho, p, v
\matches \rho'$, i.e.\ matching is undefined. A constructor pattern matches any object whose class has the
pattern's class among its ancestors; sub-patterns bind the fields of the pattern's class. An object records
its class entry, whose qualified name is the identity of the class: since a module declares each class name at
most once, the entry comparison in \ruleName{pat-constr} amounts to a comparison of qualified names.

\figref{operators} gives the operator meanings, in terms of structural equality $\eqOp$ and
membership $\memOp$ (\figrefTwo{equality}{membership}). Both are undefined where no case applies, which is where
\PurePy declines to give a comparison the meaning Python gives it (\secref{no-coercions}).
