\section{Types}
\label{sec:types}

Well-formedness gives each expression a type. A context maps a variable to its type, so $\Gamma(x) = \tau$
says that $x$ is definitely assigned and is of type $\tau$. A variable in scope but not definitely assigned
is bound to $\statusNotDefAssigned$, which is not a type, so no rule gives such a variable one; a variable
that is not in scope is undefined in $\Gamma$ (Definition~\ref{def:context}). Every parameter, return and assignment carries an annotation, so the type of a definition is given rather
than inferred from its body; within an expression, types flow in the two directions of a bidirectional
system.
\emph{Synthesis} $\Gamma \vdash e \synth \tau$ reads a type out of an expression (\figref{typing-synth}),
and \emph{checking} $\Gamma \vdash e \checks \tau$ tests an expression against a type supplied by its
surroundings (\figref{typing-check}).

Variables, literals, attribute references, calls, constructor calls, operators and subscripts synthesise.
Each literal form has a type, given by $\tyOf$:
\begin{defalign}
\tyOf(n) & = \tyInt \quad \text{($n$ an integer literal)} \\
\tyOf(n) & = \tyFloat \quad \text{($n$ a float literal)} \\
\tyOf(w) & = \tyStr \\
\tyOf(\pyinline{True}) = \tyOf(\pyinline{False}) & = \tyBool \\
\tyOf(\pyinline{None}) & = \tyNone
\end{defalign}

\noindent A class entry $C$ maps each field name to its declared type. A constructor call pairs each
argument with a field through $\fieldMap$, checks the argument against that field's type, and synthesises
the class (\ruleName{syn-constr}). In an attribute reference the object must synthesise a class, and the reference then has the type of the
field named (\ruleName{syn-attr-object}). Each binary operator has a signature $\odot : (\sigma, \sigma') \to \tau$ and each unary operator a
signature $\ominus : \sigma \to \tau$, relating operand types to result type. Subscripting has a rule for each container the subscript expression can synthesise: a list or string
subscripted by an \pyinline{int}, a dictionary by a \pyinline{str}, and a tuple by a literal index, which
must be one of its component positions, since the components have different types.

Lambdas, list, tuple and dictionary expressions and comprehensions check. Their types are not determined by
the expression alone: $\exList{}$ is a list of any element type, and a lambda has no annotations to declare
its parameter types, since Python's grammar admits none, so both take their type from the surroundings. One
rule changes direction: an expression that synthesises $\sigma$ checks against any supertype of $\sigma$
(\ruleName{check-synth}).

Subtyping (\figref{subtyping}) is reflexivity, the union rules and the ancestors of a class. Lists,
dictionaries, tuples and callables are related only by reflexivity: \pyinline{list} and \pyinline{dict} are
invariant in mypy, and \PurePy admits no program mypy rejects. A \pyinline{bool} is not an \pyinline{int},
though Python treats it as one.

A generator draws its bindings from the elements of a value, and $\elemTy$ gives the type of those elements,
mirroring $\iterOp$ (\secref{auxiliary-values}):
\begin{defalign}
\elemTy(\tyList{\tau}) & = \tau \\
\elemTy(\tyStr) & = \tyStr \\
\elemTy(\tyDict{\tau}) & = \tyStr \\
\elemTy(\tyTuple{\tau, \ldots, \tau}) & = \tau
\end{defalign}

\noindent A tuple whose component types differ has no element type, so it cannot be iterated.
