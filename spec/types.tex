\subsection{Exhaustiveness checking}
\label{sec:exhaustiveness}

\input{spec/fig/syntax-shapes}

The matching judgement decides reachability and exhaustiveness together
(\figrefTwo{pat}{pat-rows}), reachability by the shapes a case matches and exhaustiveness by the residual
left by the last case. The usefulness algorithm for ML also decides both with one
relation~\cite{maranget2007}, and the residual corresponds to the term descriptions that the match
compiler of \citet{sestoft1996} threads through the cases. Matching a pattern against a shape takes the
scrutinee's type into account, following the uncovered sets of \citet{karachalias2015}. A \emph{shape} $k$
denotes a set of values of its type $\shapeTy(k)$ (\secref{types-auxiliary}). The form $\shapeAny{\tau}{N}$ is a
value of type $\tau$ whose outermost head is not among those in $N$. A head itself denotes values: a
class its instances, an integer at a list type the lists of that length, and a literal its value. Head
typing $\Gamma \vdash h : \tau$ admits the heads whose values lie within $\tau$, and shape typing
$\Gamma \vdash k : \tau$ types each excluded head and each component of a shape
(\figref{shape-typing}). The other forms are a literal, a constructor, a tuple, a list and a dictionary, each with shapes in place of
sub-patterns. A list shape also records its element type, which the element shapes do not determine. A
constructor shape carries an excluded set of its own: $\shapeAny{\patConstr{C}{\seq{k}}}{N}$ denotes the
instances of $C$, or of a subclass not below a class of $N$, whose fields, those of $C$, have the shapes
$\seq{k}$. The shapes of $\tau$ that remain once the heads in $N$ are excluded are
$\shapesOf(\tau, N)$: one shape per member of a union, and none at all where $N$ exhausts $\tau$. No shape carries a
union or dictionary type in the form $\shapeAny{\tau}{N}$, since $\shapesOf$ is the only source of
that form: it splits a union into its members and gives a dictionary type its dictionary shape.
The rules that match sub-patterns against the form $\shapeAny{\tau}{N}$ also draw the shapes of the
component types from $\shapesOf$. The
matching judgement $\Gamma \vdash L, p \matches K, L' \binding \Delta$ divides a set of shapes into the
matched shapes $K$ and the \emph{residual} $L'$, binding $\Delta$, one shape at a time and one position at a time
(\figrefTwo{pat}{pat-rows}). A pattern that cannot match a shape has no derivation against it, so
\ruleName{pat-shapes} takes the shapes the pattern does match, which must not be none, and passes the
unmatched shapes into the residual untouched. A variable pattern binds at $\shapeTy(k)$ for the shape $k$ it matches, and a
pattern named by \pyinline{as} at the join over the shapes it matched, so a case for one alternative of a
union leaves a later variable case bound at the remaining members alone. Bindings from the positions of a row, or from
the keys of a dictionary pattern, compose by disjoint union, so a pattern that binds a name twice has no
derivation.

\begin{lemma}[Preservation of shape type]
\label{lem:shape-typing}
If $\Gamma \vdash h : \tau$ for every $h \in N$ then $\Gamma \vdash k : \tau$ for each $k \in
\shapesOf(\tau, N)$. Moreover, if $\Gamma \vdash k : \tau$ for each $k \in L$ and $\Gamma \vdash L, p
\matches K, L' \binding \Delta$ then $\Gamma \vdash k : \tau$ for each $k \in K \cup L'$.
\end{lemma}

The match rules (\figref{typing-stmt}) take the cases in the order $\dispatch$ tries them at run
time. A case that matches nothing is rejected, whether because the scrutinee can never take that shape or
because the earlier cases already cover it. The evaluation rules apply a sequence pattern only to a value
of its own kind, although Python would match either (\figref{eval-pat}); each case's pattern must
therefore agree with the scrutinee's type (\figref{agrees}), so a match on
$\tyList{\tyInt} \mathbin{|} \tyTuple{\tyInt, \tyInt}$ admits no sequence pattern. A union is exhausted
by covering each member, a class type by a pattern for the class itself, and \pyinline{bool} by
\pyinline{True} and \pyinline{False}, while \pyinline{int}, \pyinline{str} and lists have
unboundedly many heads and need a variable or wildcard. A constructor pattern whose class lies below a
class of the excluded set matches nothing, because an earlier case for the superclass took every
instance. A dictionary shape has a form of its own,
$\shapeDict{\tau}{\beta}{N}$, standing for dictionaries that hold each key of $\beta$ with a value of the
shape $\beta$ gives it, and hold no key of $N$. A dictionary pattern is taken one key at a time, no key twice
(\ruleName{pat-dict-bound}, \ruleName{pat-dict-unbound}). A key already in $\beta$ is matched against the
shape recorded for it, and a key in neither $\beta$ nor $N$ against the value type, adding to the residual the
dictionaries that lack the key. The empty pattern matches every dictionary and leaves nothing, so it alone
exhausts a dictionary type (\ruleName{pat-dict-nil}). Exhaustiveness need not come from a catch-all: over
$\tyTuple{\tyBool, \tyBool}$ the cases $\patTuple{\pyinline{True}, \patWild}$,
$\patTuple{\patWild, \pyinline{False}}$ and $\patTuple{\pyinline{False}, \pyinline{True}}$ leave nothing,
although each covers only part of the type.

\subsection{Modules and programs}
\label{sec:typing-modules}

Static loading types a module's body and computes its signature
(\figrefThree{typing-imports}{typing-import-prefix}{typing-module}). The \ruleName{module} rule types the
body as a top-level statement, and the \ruleName{predefined} rule gives a predefined module the signature
of Definition~\ref{def:predefined}.
