\section{Types}
\label{sec:types}

Well-formedness gives each expression a type. A context maps a variable to its type, so $\Gamma(x)$ is a
type $\tau$ where $x$ is definitely assigned and of type $\tau$, is $\statusNotDefAssigned$ where $x$ is in
scope but not definitely assigned, and is $\bot$ where $x$ is not in scope
(Definition~\ref{def:context}). Only the first case gives a type, so \ruleName{var} applies only to a
definitely assigned variable. Every parameter, return and assignment carries an annotation, so the type of a definition is given rather
than inferred from its body; within an expression, typing is bidirectional.
\emph{Synthesis} $\Gamma \vdash e \synth \tau$ reads a type out of an expression (\figref{typing-synth}),
and \emph{checking} $\Gamma \vdash e \checks \tau$ tests an expression against a type supplied by its
surroundings (\figref{typing-check}).

Variables, literals, attribute references, calls, constructor calls, operators and subscripts synthesise. A
literal $\ell$ synthesises the literal type $\tyLiteral{\ell}$, whose \emph{base type} is $\widen(\ell)$:
\begin{defalign}
\widen(n) & = \tyInt \quad \text{($n$ an integer literal)} \\
\widen(n) & = \tyFloat \quad \text{($n$ a float literal)} \\
\widen(w) & = \tyStr \\
\widen(\pyinline{True}) = \widen(\pyinline{False}) & = \tyBool \\
\widen(\pyinline{None}) & = \tyNone
\end{defalign}

\noindent A class entry $\clsEntry{\Gamma}{q.c}{\bind{\seq{x}}{\seq{\sigma}}}{c'}$ records the declared
type of each field it introduces, and $C(x)$ is the type of field $x$ of $C$, taken from the base class
if $x$ is inherited. A constructor call pairs each argument with a field using $\fieldMap$, checks
the argument against that field's type, and synthesises the class (\ruleName{constr}). In an attribute reference the object must synthesise a class, and the reference then has the type of the
field named (\ruleName{attr-object}). Each binary operator has a signature $\odot : (\sigma, \sigma') \to \tau$ and each unary operator a
signature $\ominus : \sigma \to \tau$, relating operand types to result type. Subscripting has a rule for each container the subscripted expression can synthesise: a list or string
subscripted by an \pyinline{int}, and a dictionary by a \pyinline{str}. A tuple has two rules, since its
components have different types: an index that synthesises a literal type in range gives the component at
that position, and any other index of type \pyinline{int} gives the union of the components.

Lambdas, list, tuple and dictionary expressions and comprehensions check. Their types are not determined by
the expression alone: $\exList{}$ is a list of any element type, and a lambda has no annotations to declare
its parameter types, since Python's grammar admits none, so both take their type from the surroundings. One
rule changes direction: an expression that synthesises $\sigma$ checks against any supertype of $\sigma$
(\ruleName{check-synth}).

Subtyping (\figref{subtyping}) is reflexivity, the widening of a literal type, the union rules and the
ancestors of a class, with \pyinline{object} above every type and \pyinline{Never} below every type. Lists,
dictionaries, tuples and callables are related only by reflexivity: \pyinline{list} and \pyinline{dict} are
invariant in mypy, and \PurePy admits no program mypy rejects. A \pyinline{bool} is not an \pyinline{int},
though Python treats it as one.

A generator draws its bindings from the elements of a value, and $\elemTy$ gives the type of those elements,
mirroring $\iterOp$ (\secref{auxiliary-values}):
\begin{defalign}
\elemTy(\tyList{\tau}) & = \tau \\
\elemTy(\tyStr) & = \tyStr \\
\elemTy(\tyDict{\tau}) & = \tyStr \\
\elemTy(\tyTuple{\tau, \ldots, \tau}) & = \tau
\end{defalign}

\noindent A tuple whose component types differ has no element type, so it cannot be iterated.

Statements carry the return type of the function they appear in as a second argument to the left of the
turnstile: $\Gamma; \tau \vdash t : R$ says that $t$ is well-formed in $\Gamma$ with result type $R$, in a
function declared to return $\tau$ (\figref{typing-stmt}). The type $\tau$ is an obligation on the
\pyinline{return} statements within $t$ rather than a property of $t$, so every rule passes it down
unchanged. A \pyinline{return} checks its expression against $\tau$, and a bare
\pyinline{return} requires $\tau$ to admit \pyinline{None}. An assignment takes its type from its
annotation and checks the expression against it; the conditions of \pyinline{if} and \pyinline{assert}
check against \pyinline{bool}, and an assertion message against \pyinline{str}.

A function definition binds its parameters at their annotated types and its own name, and the names of the
region it belongs to, at the corresponding $\pyinline{Callable}$ type; the variables the body assigns start
at $\statusNotDefAssigned$, as they do without types (\ruleName{def}). The body is checked with the
declared return type, and must have result type $\Returns$ unless the function returns \pyinline{None},
so a function that declares a result definitely returns one.

A \pyinline{match} subject synthesises a type, and each pattern checks against it, binding its variables at
the types of the positions they match (\figref{typing-pat}). A constructor pattern requires its class to be
a subtype of the subject's type, so a case that cannot match is rejected rather than being merely
unreachable.

Merging two branches merges their contexts pointwise. A variable definitely assigned in both, at $\tau$ and
$\tau'$, is of type $\joinTy(\tau, \tau')$. Writing the \emph{members} of a type for its operands where it
is a union and for the type itself otherwise, $\joinTy(\tau, \tau')$ is the union of the members of $\tau$
and $\tau'$, less any member that is a subtype of another, and is that member alone where one remains.
Joining a type with itself gives that type, joining a class with one of its ancestors gives the ancestor,
and joining \pyinline{int} with \pyinline{str} gives $\tyUnion{\tyInt}{\tyStr}$. A variable definitely
assigned in one branch alone is $\statusNotDefAssigned$.
