\section{Well-formedness}
\label{sec:well-formedness}

\PurePy excludes some Python behaviours statically and others only at runtime.
Well-formedness is the static part, a judgement on programs defined in this \seckind{}; the operational
semantics (\secref{operational-semantics}) is defined for well-formed programs. A program is well-formed
when it is well typed, so the rules of this \seckind{} give each expression a type, each statement a
static outcome recording either the assignments made or the fact that the statement definitely returns,
and each module a signature. The \seckind{} introduces
types and subtyping, then follows the syntax of \secref{syntax}, taking statements, expressions and
patterns, then modules and programs, and \secref{operational-semantics} gives each of these a dynamic
counterpart.

\speconly{The rules for variables serve two aims: that a program has no mutable state, so a variable never
changes value, and that a well-typed program is also well typed under mypy\Added{ (the restrictions this imposes are collected in \secref{mypy-restrictions})}. Within these limits the rules permit
as much as possible. For the first aim, a variable is introduced by a declaration, parameter, import, pattern or
generator, and is assigned at most once, either in its declaration or afterwards; an assignment never introduces
a variable nor reassigns one.
For the second, a scope is the body of a module, function, lambda or comprehension, as in Python, and the
builtins enclose every module; a scope declares a name at most once and may shadow a name of an enclosing scope,
hiding it throughout the scope.}

\subsection{Types}
\label{sec:types}

\input{spec/fig/resolve-name}
\input{spec/fig/resolve-type}

Function signatures, assignments and dataclass fields are annotated with type expressions, and a
type expression denotes a type under a context and class table (\figref{resolve-type}). Every definition carries an
annotation for its parameters and return type, so the type of a definition is given rather than
inferred from its body. Within a type expression, a class name applied to as many type arguments as the class has parameters resolves to an instantiated class, an alias name applied to type arguments resolves to the instantiation of its alias, type parameters in scope denote the type variables of those names, and all other names must be predefined names (\figref{resolve-type}). The function $\baseType(\tau)$ discards the precision of a
literal type, taking $\tyLiteral{42}$ to \pyinline{int} and otherwise acting as the identity
(\paperonly{\figref{auxiliary-functions}}\speconly{\S\ref{aux:base-type}}).

\speconly{\subsubsection{Subtyping}\label{sec:subtyping}}%
\paperonly{\paragraph{Subtyping.}}

Subtyping (\figref{subtyping}) has every type below itself, a literal type below its base type, and an instantiated class $C[\seq{\tau}]$ below every type that its base class is below, once $\seq{\tau}$ is substituted into the arguments of the base (\ruleName{subty-class-extend}), and below $C[\seq{\sigma}]$ when $\seq{\tau}$ and $\seq{\sigma}$ are equivalent (\ruleName{subty-class}), so that type arguments are invariant, as for lists and dictionaries; a type variable is below itself and \pyinline{object} alone, with \pyinline{object} above every type and \pyinline{Never} below every type. \Replaced{A type that is not a union has one \emph{disjunct}, the type itself; the disjuncts of a union $\tyUnion{\sigma}{\tau}$ are the disjuncts of $\sigma$ together with the disjuncts of $\tau$.}{The \emph{members} of a union $\tyUnion{\sigma}{\tau}$ are the members of $\sigma$ and of $\tau$, and any other type is its own only member.} A union is above
each of its \Replaced{disjuncts}{members} and below every type that is above all of them. A tuple type is covariant, below another of the
same length when each of its components is below the corresponding component. Two types are \emph{equivalent}, $\sigma \tyEquiv \tau$, when each is a subtype of the other; the notations $\subty$ and $\tyEquiv$ follow \citet{pierce2002}. Lists and
dictionaries are related only when their components are equivalent, since both are invariant in mypy\Added{ (\paperonly{\secref{python-compatibility}}\speconly{\secref{mypy-restrictions}})}. A callable type is contravariant in its parameters
and covariant in its result, following mypy. The types with a length, namely lists, dictionaries,
strings and tuples, are below \pyinline{Sized}. An \pyinline{int} is a \pyinline{float}, as PEP~484
requires, so \pyinline{x: float = 0} is well typed. A \pyinline{bool} is not an \pyinline{int}, although
Python treats it as one.

\begin{lemma}[Transitivity of subtyping]
\label{lem:subtyping-transitive}
If $\Sigma \vdash \sigma \subty \tau$ and $\Sigma \vdash \tau \subty \tau'$ then $\Sigma \vdash \sigma \subty \tau'$.
\end{lemma}

\noindent Subtyping is therefore a preorder: reflexive and transitive but not antisymmetric,
because distinct types such as $\tyUnion{\sigma}{\tau}$ and $\tyUnion{\tau}{\sigma}$ are
equivalent.

Two types are \emph{comparable}
when either is a subtype of the other. Two comparable types
\emph{join} to the larger type and two incomparable types to their union. Two comparable types \emph{meet} to the smaller type; a
meet of incomparable types distributes over a union, takes tuples componentwise and callables with
parameters joined and results combined using meet, and is \pyinline{Never} otherwise, since no value belongs to both types.
So joining a type with itself gives that type, joining a class with its base class gives the base class, and
joining \pyinline{int} with \pyinline{str} gives $\tyUnion{\tyInt}{\tyStr}$. A sequence of types is joined by
folding binary join over the sequence, with \pyinline{Never} as the unit (\paperonly{\figref{auxiliary-functions}}\speconly{\S\ref{aux:join}}).

\begin{lemma}[Types form a lattice]
\label{lem:lattice}
Types ordered by subtyping in $\Sigma$, up to equivalence, form a bounded distributive lattice: $\joinTy{\Sigma}{\sigma}{\tau}$
is the least upper bound of $\sigma$ and $\tau$, $\meetTy{\Sigma}{\sigma}{\tau}$ is their greatest lower bound,
\pyinline{object} is the greatest type and \pyinline{Never} the least.
\end{lemma}

\subsection{Expressions}
\label{sec:expression-typing}

Within an expression the typing judgement gives each subexpression a type, and
is bidirectional. \emph{Synthesis} $\Sigma; \Gamma \vdash e \synth \tau$ reads a type out of an expression (\figrefThree{typing-synth}{typing-synth-elim}{typing-synth-ctd}),
and \emph{checking} $\Sigma; \Gamma \vdash e \checks \tau$ tests an expression against a type supplied by its
surroundings (\figref{typing-check}). The division follows the usual recipe for bidirectional
systems~\cite{davies2000,dunfield2021}: introduction forms check, since a lambda's parameters cannot be
annotated and an empty list does not determine its element type, and elimination forms synthesise, since a call, a subscript or an attribute
reference starts from a subterm whose type is known. Type systems that follow the recipe strictly usually
rely on an annotation form $(e \mathbin{:} \tau)$, which synthesises by construction, so a checking form
written with an annotation can be used in any context where synthesis is required. Python has no such form,
allowing annotations only on parameters, returns and assignments, so \PurePy gives each introduction form
a synthesis rule wherever its parts determine the type; Swift, Kotlin and Scala
take similar approaches for similar reasons~\cite{swift2025,kotlin2025,odersky2025}.

Variables, literals, attribute references, calls, constructor calls, operators and subscripts synthesise.
The \ruleName{var} rule applies whenever $\Gamma(x)$ is a type, so a variable that is not definitely
assigned has no rule. A
literal $\ell$ synthesises the literal type $\tyLiteral{\ell}$.

\input{spec/fig/typing-synth}

The fields of a class $C$ form a field scheme $\fields(\Sigma, C)$ over its type parameters, with one binding $\bind{x}{\tau}$ per
field: the fields of its base class first, recursively and instantiated at the type arguments of the base, then the fields declared by $C$ itself, each at its
declared type; the fields of an instantiated class $C[\seq{\tau}]$ are the instantiation $\tyInst{\fields(\Sigma, C)}{\seq{\tau}}$. The order matters, because a constructor call pairs positional arguments with fields by
position. A constructor call $\exConstr{q}{a}$ pairs each argument with a field using
$\fieldMap$, checks it against that field's type, and synthesises the class $C$ that $q$ resolves to
(\ruleName{constr}). An attribute reference $\exAttr{e}{x}$ has the type of the field $x$ of the class synthesised by $e$
(\ruleName{attr-object}). The signature of a predefined module binds
$\pymath{\_\_name\_\_}$ at $\tyStr$ and each member at the type listed for it
(\figref{predefined-signatures}, Definition~\ref{def:predefined}). A module attribute reference
$\exAttr{e}{x}$ resolves as a qualified name to a definitely assigned member
(\ruleName{attr-module})\paperonly{; see \secref{no-load-dependent}}. A variable bound to a module or
class is not an expression on its own, and occurs only as the head of a qualified
name\paperonly{ (\secref{no-first-class})}.
In a subscript $\exSubscript{e}{e'}$ there is a rule for each container that $e$ can synthesise: a list
(\ruleName{subscript-list}) or string (\ruleName{subscript-str}) with $e'$ of type \pyinline{int}, and a
dictionary with $e'$ of type \pyinline{str} (\ruleName{subscript-dict}). Tuples have three rules: an index
that synthesises a literal type gives the component type at that position, counting from the end when the index
is negative (\ruleName{subscript-tuple}, \ruleName{subscript-tuple-neg}), and any other index of type
\pyinline{int} gives the join of the component types (\ruleName{subscript-tuple-int}). \Deleted{A negated numeric
literal synthesises the negated literal type (\ruleName{unop-literal}), and \ruleName{unop} excludes that
form, to keep the judgement deterministic.} A subscript, attribute reference or call whose subject
synthesises a union is typed at each \Replaced{disjunct}{member}, with a variable in place of the subject, and synthesises the
join of the results (\ruleName{subscript-union}, \ruleName{attr-union}, \ruleName{call-union}); generators need no
such rule, because $\elemTy$ takes a union to the join of its \Replaced{disjuncts'}{members'} element types.
\citet{dunfield2004} state union elimination once, for an arbitrary evaluation context; here union elimination is
stated separately for each elimination form.

Lambdas check, as do lists, tuples, dictionaries and comprehensions. An expression that synthesises $\sigma$ checks against any supertype
of $\sigma$ (\ruleName{check-synth}), which applies only when no other rule concludes $\Sigma; \Gamma \vdash e \checks
\tau$, so both judgements are
syntax-directed and an expression has at most one derivation in each.

\input{spec/fig/typing-check}

The forms that synthesise are conditional expressions when a branch
synthesises, at the join of the two types when both branches synthesise and otherwise at the
synthesising branch's type, the other branch checking against it (\ruleName{syn-cond});
tuples when every component synthesises (\ruleName{syn-tuple}); comprehensions when the body
synthesises (\ruleName{syn-list-comp}, \ruleName{syn-dict-comp}); and non-empty lists and
dictionaries when at least one element synthesises, the remaining elements checking against the join
of the base types of the synthesising elements (\ruleName{syn-list}, \ruleName{syn-dict}). A list,
dictionary or comprehension takes the base type of the type synthesised by its elements or body, since
\pyinline{list} and \pyinline{dict} are invariant and a literal element type would keep the container from
matching any other element type. An empty list or dictionary and a lambda have no
synthesis rule at all, so checking is the only way to type them. A lambda applied to arguments is the
exception, since the arguments give the parameter types, and the call then synthesises the type of the body
or checks the body against an expected type (\ruleName{syn-call-lambda}, \ruleName{call-lambda}). \Added{The parameters of a
lambda must be distinct, as for a function.} A non-empty list has both, and the
checking rule is still needed when the expected element type is wider than the type synthesised by the
elements, since \pyinline{list} is invariant.

Typing a comprehension types its qualifiers, which bind the variables that can be used in the body
(\figref{typing-check}). A generator's variable is bound at $\elemTy$ of the type synthesised by the
iterated expression (\paperonly{\figref{auxiliary-functions}}\speconly{\S\ref{aux:elem-type}}). A
tuple is iterated at the join of the base types of its components.
A lambda within a comprehension may not capture a generator variable, a side condition of
\ruleName{list-comp}, \ruleName{dict-comp} and \ruleName{qual-generator}. Python closures are
late-binding and the comprehension rebinds the variable on each iteration, so the lambda would see the
variable's final value; in \PurePy a lambda is only able to see the value of the generator variable at
each iteration.

\speconly{\subsubsection{Operators}\label{sec:well-formedness-operators}}%
\paperonly{\paragraph{Operators.}}

\input{spec/fig/operator-overloads}

Each operator is overloaded as specified in \figref{operator-overloads}. A \emph{resolved overload}
$((\tau_1, \tau_2), \tau)$ pairs operand \emph{bounds}
with a result type; the judgements of the figure relate operand
types to the resolved overloads of an operator. The \ruleName{binop} and \ruleName{unop} rules (\figref{typing-synth}) take the result type
of the most specific overload at the operand types, $\resolveOp$ (\paperonly{\figref{auxiliary-functions}}\speconly{\S\ref{aux:resolve-op}}), so \pyinline{1 + 2} is an
\pyinline{int} and \pyinline{1 + 2.0} a \pyinline{float}.

An \emph{equality type} is one for which structural equality is
defined:
\begin{defalign}
& \Sigma \vdash \nu \eqType \\
& \Sigma \vdash \tyLiteral{\ell} \eqType \\
& \Sigma \vdash \tyList{\tau} \eqType && \qquad\quad \text{if } \Sigma \vdash \tau \eqType \\
& \Sigma \vdash \tyDict{\tau} \eqType && \qquad\quad \text{if } \Sigma \vdash \tau \eqType \\
& \Sigma \vdash \tyTuple{\seq{\tau}} \eqType && \qquad\quad \text{if } \Sigma \vdash \tau_i \eqType \quad (\forall i) \\
& \Sigma \vdash \tyUnion{\sigma}{\tau} \eqType && \qquad\quad \text{if } \Sigma \vdash \sigma \eqType \text{ and } \Sigma \vdash \tau \eqType \\
& \Sigma \vdash C[\seq{\sigma}] \eqType && \qquad\quad \text{if } \Sigma \vdash \tau \eqType \text{ for each } \bind{x}{\tau} \in \tyInst{\fields(\Sigma, C)}{\seq{\sigma}}
\end{defalign}

\noindent A callable type is not an equality type, and neither is any type with a callable component, so
comparing two functions is rejected statically. The final rule of each table closes the
judgement under base-typing, letting \pyinline{1 == 0} use the equality overload at \pyinline{int}, since
two distinct literal types are not comparable; \pyinline{2 ** 3} is still an \pyinline{int}, since the
direct instance's bounds $(\tyInt, \tyLiteral{3})$ lie below the base instance's
$(\tyFloat, \tyFloat)$. For this operator the \ruleName{binop} rule is more precise than mypy, whose
overloads give \pyinline{Any} whenever the exponent is not a literal, whereas the most specific overload resolves to
\pyinline{float}.

\begin{lemma}[Most specific overload]
\label{lem:most-specific-overload}
If neither $\sigma_1$ nor $\sigma_2$ is a subtype of \pyinline{Never} and some overload of $\odot$ applies at
$(\sigma_1, \sigma_2)$, then $\resolveOp(\Sigma, \odot, \sigma_1, \sigma_2)$ is defined\Replaced{, and similarly for}{; likewise}
$\resolveOp(\Sigma, \ominus, \sigma)$.
\end{lemma}

\subsection{Statements}
\label{sec:well-formedness-statements}

A well-typed statement has a \emph{static outcome} $R$: either $\Returns$, when the statement \emph{definitely
returns}, or $\Assigns{\Delta}$ for a context $\Delta$ with an entry for any variable declared or assigned by the
statement (Definition~\ref{def:context}), recording whether the variable is definitely assigned, definitely
unassigned or possibly unassigned after the statement.

\input{spec/fig/typing-top-level}

Context operations $\override$ and $\merge$ lift to a right semiring over static outcomes $R$, with $\Assigns{\varnothing}$ as left and right unit for $\override$ and $\Returns$ as unit for $\merge$ and zero for $\override$.

\begin{definition}[Override and merge on static outcomes]
\begin{defalign}
\Assigns{\Delta} \merge \Assigns{\Delta'} & = \Assigns{\Delta \merge \Delta'} \\
R \merge \Returns = \Returns \merge R & = R \\
\\
\Assigns{\Delta} \override \Assigns{\Delta'} & = \Assigns{\Delta \override \Delta'} \\
R \override \Returns = \Returns \override R & = \Returns
\end{defalign}
\end{definition}

\noindent The $\Returns \override R$ case never arises because statement typing excludes unreachable statements\paperonly{ (\secref{unreachable})}.

\paperinput{paper/well-formedness/match-cases}%

The statement judgement $\Sigma; \Gamma; \zeta \vdash s : R$ says that under $\Gamma$ and
optional return type $\zeta$, statement $s$ has static outcome $R$ (\figref{typing-stmt}); every rule passes $\zeta$ down unchanged.
A sequence $s\;s'$ (\ruleName{seq}) types $s$, then types $s'$ under $\Gamma$ overridden by the context assigned
by $s$. A conditional combines its
branches with $\merge$, merging in $\Assigns{\varnothing}$ when there is no \pyinline{else} branch.
Top-level statements are checked by a separate
judgement, $\Sigma; q; \Gamma \vdash t : R \binding \Sigma'$ (\figref{typing-top-level}): a sequence composes in the same way as a statement sequence, \Replaced{class
declarations and \pyinline{type} statements are top-level forms}{a class declaration is a top-level form}, and a plain statement is checked with no return type
(\ruleName{top-stmt}), so a \pyinline{return} has no derivation at the top level. A
\pyinline{return} checks its expression against $\zeta$, which must be of the form $\tau$, and a bare
\pyinline{return} requires \Replaced{$\tau$ to be equivalent to \pyinline{None}}{\pyinline{None} to be a subtype of $\tau$}. An expression statement synthesises a type and discards it
(\ruleName{expr-stmt}). A call to a callable with result \tyNone{} is not an expression, because
\ruleName{call} requires a result other than \tyNone, and is typed as a statement by \ruleName{call-stmt}.
\Replaced{The restriction is for compatibility with mypy (\paperonly{\secref{python-compatibility}}\speconly{\secref{mypy-restrictions}}).}{The restriction exists only for compatibility with mypy, which rejects any use of the value of such a call.}

A variable declaration $x\exAnnot{\psi}$ introduces $x$ at the type denoted by $\psi$, without assigning it
(\ruleName{declare}); an assignment $\exAssign{x}{e}$ requires $x$ to be a declared but unassigned variable, and
checks $e$ against its declared type (\ruleName{assign}); the form $\exAssign{x\exAnnot{\psi}}{e}$ declares and
assigns $x$ at once (\ruleName{declare-assign}). A declaration does not check
whether its name is already declared; that check is made once for the whole scope, when the rules for function
definitions and modules introduce the variables of the scope as unbound, using the function $\scopeS(Y, s)$
(\paperonly{\figref{auxiliary-functions}}\speconly{\S\ref{aux:scope}}).

The conditions of \pyinline{if} and \pyinline{assert}
check against \pyinline{bool}, and an assertion message against \pyinline{str}. A class declaration binds
the class name to $\Type{C}$, resolves the field annotations with its type parameters in scope, and requires the fields it declares to be distinct and, when it extends
another class, the base to \Added{name a class rather than an alias and to} resolve to an instantiated class, and the additional fields not to repeat an inherited field
(\ruleName{class}, \ruleName{class-extend}). Class declarations also require the predefined name \pyinline{dataclass} (\figref{predefined-signatures}) to be in
scope; every \PurePy class must declare itself a dataclass. \Added{A \pyinline{type} statement $\exTypeAlias{x[\seq{\alpha}]}{\psi}$, such as \pyinline{type Pair[T] = tuple[T, T]},
declares $x$ as an alias of the type denoted by $\psi$ with the type parameters $\seq{\alpha}$ in scope
(\ruleName{type-alias}). An application of the alias such as \pyinline{Pair[int]} denotes that type at the given
arguments (\ruleName{ty-alias}), here \pyinline{tuple[int, int]}, so types never mention aliases. Since the names declared by a module are unbound
before their declarations (\secref{well-formedness-modules}), $\psi$ can name only classes and aliases declared
earlier in the module, and cannot name $x$ itself.} Each rule that takes an annotation resolves it to a type
(\figref{resolve-type}).

A mutual region of function definitions (\ruleName{def}) resolves the annotations of each definition to a
\pyinline{Callable} type (\ruleName{def-signature}, \figref{typing-def}), binds the names of the mutual region,
including the name of each function itself, at those types, and checks each definition against its type
(\ruleName{def-body}). A definition binds its parameters at their annotated types; variables declared or
assigned in the body start unbound, emulating Python's scoping of function bodies, which
prefers a locally bound name to one visible in an enclosing scope. A variable of the
enclosing scope referenced by the body must be definitely assigned at the point at which the function is defined,
whereas Python resolves the reference only when the body runs. As with any scope, the names declared in the function, including
its parameters, must be distinct from one another and from any pattern variables in its body. The function names of the mutual region are not among these; they are
declared in the enclosing scope, where the same condition applies to them. The body is checked with the
declared return type, and must have static outcome $\Returns$ unless \Replaced{the return type is equivalent to \pyinline{None}}{the function returns \pyinline{None}},
so a function that declares a result definitely returns one. \Added{A return type such as $\tyUnion{\tyInt}{\tyNone}$
does not exempt the body from returning, nor permit a bare \pyinline{return}, for compatibility with mypy (\paperonly{\secref{python-compatibility}}\speconly{\secref{mypy-restrictions}}).}

A \pyinline{match} scrutinee synthesises a type $\sigma$, and its cases $\seq{b}$ are checked in turn by the
auxiliary judgement \Replaced{$\Sigma; \Gamma; \zeta \vdash \tau, L, \seq{b} : S, \tau', L'$}{$\Sigma; \Gamma; \zeta; \sigma \vdash L, \seq{b} : S, L'$} (\figref{typing-cases}), which threads
\Replaced{a remaining type, starting from $\sigma$, and a residual $L$ of shapes, starting from the shapes of $\sigma$ (\figref{shapes}),
through the cases, merging their outcomes into $S$}{a residual $L$ of shapes through the cases, starting from the shapes of $\sigma$ (\figref{shapes}), and merges
their outcomes into $S$}. The \ruleName{match} rule applies when the \Replaced{final remaining type}{remaining type
$\remaining(\Sigma, \Gamma, \sigma, \seq{p})$ for the patterns $\seq{p}$ of the cases
(\paperonly{\figref{auxiliary-functions}}\speconly{\S\ref{aux:remaining}})} is $\tyNever$, meaning the match is
exhaustive; the \ruleName{match-partial} rule applies otherwise\Replaced{ and also merges in $\Assigns{\varnothing}$, the
outcome of the path on which the scrutinee is not matched by any of the cases}{, merging in $\Assigns{\varnothing}$
for the values that fall through}. The \Added{remaining type, the} residual, reachability and exhaustiveness are the subject of
\secref{well-formedness-patterns}.

usefulness algorithm for ML~\cite{maranget2007} also checks reachability and exhaustiveness with a single

sets of \citet{karachalias2015} likewise let the type exclude cases.

\speconly{\subsubsection{Pattern checking}\label{sec:pattern-checking}}%
\paperonly{\paragraph{Pattern checking.}}

\input{spec/fig/pattern-matching/checking-pat}

A pattern must \emph{check} against the \Replaced{remaining type}{scrutinee type}, $\Sigma; \Gamma \vdash p \checks \tau \added{\binding \Delta}$ (\figref{checking-pat}), before it is matched against the residual (\ruleName{match-case}). \Added{The bindings $\Delta$ give the types of the pattern variables.} The judgement holds when every tuple pattern in $p$ is at a type which has no list values, every list pattern is at a type which has no tuple values, and every constructor pattern is at a type with at most one comparable instantiation of its class, up to equivalence. List values and tuple values are defined by subtyping:
\begin{defalign}
\tau \text{ has list values} & {}\iff \Sigma \vdash \tyList{\sigma} \subty \tau \text{ for some } \sigma \text{, or a \replaced{disjunct}{member} of } \tau \text{ is a type variable} \\
\tau \text{ has tuple values} & {}\iff \Sigma \vdash \tyTuple{\seq{\sigma}} \subty \tau \text{ for some } \seq{\sigma} \text{, or a \replaced{disjunct}{member} of } \tau \text{ is a type variable}
\end{defalign}
So list types, $\tySized$ and $\tyObject$ have list values; tuple types, $\tySized$ and $\tyObject$ have tuple values; and a type variable, which may stand for any type, has both. The rules check a sub-pattern at the type of its position, a tuple component, list element, dictionary value or field, and a pattern at a union at each of its \Replaced{disjuncts}{members}. \Added{A variable pattern binds at the type at which it is checked, and a pattern named by \pyinline{as} is bound at $\matchedAs(\Sigma, \Gamma, \tau, p)$; the bindings of sub-patterns compose by disjoint union, so a pattern that binds a name twice is ill-formed, and at a union the bindings of the disjuncts are joined.} \Replaced{A pattern also checks against a type which has no disjunct of the form matched by the pattern: a tuple pattern when no disjunct is a tuple type of the pattern's length, a list pattern when no disjunct is a list type, a dictionary pattern when no disjunct is a dictionary type, or a constructor pattern when its class has no comparable instantiation (\ruleName{check-tuple-none}, \ruleName{check-list-none}, \ruleName{check-dict-none}, \ruleName{check-constr-none}). Such a pattern matches no shape of the type and binds its variables at $\tyNever$, the unit of the join. At one disjunct of a union it therefore leaves the values of that disjunct to later cases, and a case with a pattern matching no shape at all is unreachable.}{A pattern also checks against a type when it cannot match any value of that type, as with a tuple pattern at a tuple type of another length or a constructor pattern naming a class with no comparable instantiation (\ruleName{check-tuple-none}, \ruleName{check-list-none}, \ruleName{check-dict-none}, \ruleName{check-constr-none}); matching then leaves the values of the type to later cases.}

The conditions on tuple and list patterns ensure that pattern matching always has a result. Under the evaluation rules, matching a tuple pattern against a list or a list pattern against a tuple is undefined\speconly{ (\figref{eval-pat})}, although Python permits both. Both forms of pattern therefore fail at $\tyList{\tyInt} \mathbin{|} \tyTuple{\tyInt, \tyInt}$, at $\tySized \mathbin{|} \tyTuple{\tyInt, \tyInt}$, and at a type variable.

The condition on constructor patterns supplies the type arguments omitted by the pattern: they are recovered by the judgement $\Sigma \vdash C[\seq{\sigma}] \instanceAt \tau$ from the type $\tau$ at which the pattern is checked, the \emph{instance} of $C$ at $\tau$ being the instantiation of $C$ above $\tau$, or the instantiation below $\tau$, when there is one up to equivalence (\ruleName{instance-above}, \ruleName{instance-below}). Below $C$ the base classes of the type determine the instance: at \pyinline{IntLeaf}, a subclass of \pyinline{Leaf[int]}, the instance of \pyinline{Leaf} is \pyinline{Leaf[int]}. Above $C$ the base arguments of $C$ determine it: at \pyinline{Tree[int]} the instance of \pyinline{Leaf} is \pyinline{Leaf[int]}, because \pyinline{Leaf[T]} extends \pyinline{Tree[T]}, whereas at \tyObject{} a class with type parameters has no instance, since every instantiation lies below \tyObject.
\begin{AddedBlock}
The instance judgement is decided as follows. A pattern is checked at the disjuncts of a union separately
(\ruleName{check-union}), so the type $\tau$ at which an instance is taken is never a union. If $\tau$ is an
instantiated class $D[\seq{\rho}]$ with $C$ an ancestor of $D$, the instance is the instantiation of $C$ reached
from $D[\seq{\rho}]$ along the base classes, which is unique because type arguments are invariant
(\ruleName{instance-above}). If $\tau$ is $D[\seq{\sigma}]$ with $D$ an ancestor of $C$, the instantiations of $C$
below $\tau$ are the $C[\seq{\tau}]$ for which the instantiation of $D$ reached from $C[\seq{\tau}]$ along the base
classes has arguments equivalent to $\seq{\sigma}$, and Lemma~\ref{lem:instantiation-candidates} bounds the instantiations
to be examined to finitely many instantiation candidates: one instantiation candidate up to equivalence gives the instance
(\ruleName{instance-below}), none means that $C$ has no instance at $\tau$, and two that are not equivalent mean
that $C$ has an instantiation comparable with $\tau$ but no instance, so that a constructor pattern at $\tau$ is
ill-formed. At \tyObject{} and at \tyNever{} every instantiation of $C$ is comparable with $\tau$, so $C$ has an
instance only if it has no type parameters. At any other type $C$ has no instantiation comparable with $\tau$, and no instance.
\begin{lemma}[Sufficiency of instantiation candidates]
\label{lem:instantiation-candidates}
Suppose $D \in \ancestors(\Sigma, C)$. An \emph{instantiation candidate} for $C$ at $D[\seq{\sigma}]$ is an instantiation $C[\seq{\tau}]$ in
which each $\tau_i$ is the join of a subset of $\subterms(\seq{\sigma}) \cup \set{\tyObject}$
(\paperonly{\figref{auxiliary-functions}}\speconly{\S\ref{aux:subterms}}). If any instantiation of $C$ is below
$D[\seq{\sigma}]$, then some instantiation candidate is below $D[\seq{\sigma}]$; and if two instantiations of $C$ that are not equivalent
are below $D[\seq{\sigma}]$, then two instantiation candidates below $D[\seq{\sigma}]$ are not equivalent.
\end{lemma}
\end{AddedBlock}

\speconly{\subsubsection{Shapes and shape typing}\label{sec:shapes}}%
\paperonly{\paragraph{Shapes and shape typing.}}

\input{spec/fig/pattern-matching/shapes}

A shape $k$ (\figref{shapes})
denotes a set of values of its type $\shapeTy(k)$ (\paperonly{\figref{auxiliary-functions}}\speconly{\S\ref{aux:shape-type}}). The form $\shapeAny{\tau}{H}$ denotes the
values of type $\tau$ whose outermost head is not among those in $H$; the other forms are constructor,
tuple, list and dictionary shapes, each with shapes in place of sub-patterns. A list shape also records its
element type, which the element shapes do not determine. A constructor shape also carries an excluded
set: $\shapeAny{\patConstr{C[\seq{\tau}]}{\seq{k}}}{H}$ denotes the instances of $C[\seq{\tau}]$, or of any subclass not below a
class of $H$, whose fields, those of $C$, have shapes $\seq{k}$. A rest shape at a class type denotes
the same values as the constructor shape with a rest shape at each field, and is expanded into that
form only by splitting (\figref{split}): a class may refer to itself through its fields, so expanding
in advance would not terminate.

A head itself denotes a set of values: a literal its value, a class its instances, and $\headList{n}$
the lists of length $n$. Head typing $\Sigma \vdash h : \tau$ holds when the values of $h$ lie within
$\tau$. Shape typing $\Sigma \vdash k : \tau$ holds when $\shapeTy(k)$ is a subtype of $\tau$ and $k$ is
well-formed: each excluded head is typed at the type of the shape (at $\tyStr$, for the keys of a
dictionary shape) and each component shape at the type of that component.

The auxiliary function $\shapes(\Sigma, \tau, H)$ (\paperonly{\figref{auxiliary-functions}}\speconly{\S\ref{aux:shapes}}) gives the shapes of $\tau$
once the heads in $H$ are excluded. A union contributes the shapes of its \Replaced{disjuncts}{members} and a dictionary type
the dictionary form; every other type contributes the single shape $\shapeAny{\tau}{H}$, or no shape at
all when $H$ exhausts $\tau$. The rest form therefore never carries a union or dictionary type, and
\ruleName{shape-rest} states this restriction as a side condition.

\speconly{\subsubsection{Matching}\label{sec:matching}}%
\paperonly{\paragraph{Matching.}}

\input{spec/fig/pattern-matching/typing-pat}

\emph{Matching} (\figref{typing-pat}) has three forms. The form on a single shape $k$ matches a pattern against that
shape, giving matched shapes $K$\Replaced{ and residual $L$}{, residual $L$ and bindings $\Delta$}. \Deleted{A variable pattern binds at
$\shapeTy(k)$, and a pattern named by \pyinline{as} at the join over the matched shapes, so a case for
one alternative of a union leaves a later variable case bound at the remaining members alone.} The form
on sequences matches the sub-patterns of a tuple, list, dictionary or constructor pattern against the
component shapes position by position\Deleted{, and the bindings of the positions, or of the keys of a dictionary
pattern, compose by disjoint union, so a pattern that binds a name twice has no derivation}. The form on
an ordered set of shapes $L$, used by the match rules, matches each shape of $L$ in turn. \Replaced{The pattern need not match every shape of $L$, so \ruleName{pat-shapes} takes the shapes of $L$
matched by the pattern, of which there must be at least one, and passes the unmatched shapes into the
residual untouched.}{Some shapes of
$L$ may admit no derivation for the pattern, so \ruleName{pat-shapes} takes the shapes of $L$ that do
admit a derivation, of which there must be at least one, and passes the remaining shapes into the
residual untouched.}

\input{spec/fig/pattern-matching/split}

A pattern matches a shape directly if the shape has the head tested by the pattern. Otherwise the shape
is first \emph{split} by the auxiliary judgement $\Sigma; \Gamma \vdash k, p \splits K, L$ (\figref{split}):
the shapes $K$ have the head tested by $p$, with the shapes of the component types drawn from $\shapes$,
and the residual $L$ is the shape $k$ with that head excluded as well. The \ruleName{pat-split} rule matches
the pattern against $K$ and adds $L$ to the residual. Only the forms
with an excluded set split, and no head types at a tuple type, so the excluded set of a tuple shape is
empty and \ruleName{split-tuple} leaves the empty residual.
A constructor pattern whose class lies below a
class of the excluded set matches nothing, because an earlier case for the superclass has already
matched every instance. A constructor pattern matches the instance of its class at the type of the shape (\figref{instance}): a pattern \pyinline{Leaf(v)} at \pyinline{Tree[int]} matches \pyinline{Leaf[int]} and binds \pyinline{v} at \pyinline{int}.

A dictionary shape has a separate form,
$\shapeDict{\tau}{\beta}{H}$, standing for the dictionaries that hold each key $w$ in the domain of
$\beta$ with a value of shape $\beta(w)$, but that hold no key of $H$. A dictionary pattern takes its keys in order, with no key occurring twice. A key in
neither $\beta$ nor $H$ splits the shape at that key (\ruleName{split-dict}), adding to the residual the
dictionaries that lack the key; once every key of the pattern is in $\beta$ the keys match as a sequence
(\ruleName{pat-dict}), each key $w$ against $\beta(w)$. The empty dictionary pattern matches every
dictionary and leaves the empty residual.

The cases needed to exhaust a match therefore depend on the type of the scrutinee: a union is exhausted
by covering each \Replaced{disjunct}{member}, a class type by a pattern for the class itself, \pyinline{bool} by
\pyinline{True} and \pyinline{False}, and a dictionary type by the empty dictionary pattern, while \pyinline{int}, \pyinline{str} and lists have
unboundedly many heads and need a variable or wildcard. A literal-typed scrutinee is exhausted by covering
its literals, so \Replaced{\pyinline{x: Literal[42] = 42}}{\pyinline{x = 42}} admits a match with a case for \pyinline{42} alone, while
\pyinline{x: int = 42} keeps the type open. Over
$\tyTuple{\tyBool, \tyBool}$ the cases $\patTuple{\pyinline{True}, \patWild}$,
$\patTuple{\patWild, \pyinline{False}}$ and $\patTuple{\pyinline{False}, \pyinline{True}}$ leave the empty residual,
although each covers only part of the type.

\begin{lemma}[Preservation of shape type]
\label{lem:shape-typing}
If $\Sigma \vdash h : \tau$ for every $h \in H$ then $\Sigma \vdash k : \tau$ for each $k \in
\shapes(\Sigma, \tau, H)$. Moreover, if $\Sigma \vdash k : \tau$ for each $k \in L$ and $\Sigma; \Gamma \vdash L, p
\matches K, L' \deleted{\binding \Delta}$ then $\Sigma \vdash k : \tau$ for each $k \in K \disjunion L'$.
\end{lemma}

\subsection{Modules and programs}
\label{sec:well-formedness-modules}

\emph{Static loading} types a module's body and computes its signature $\Gamma$, the judgement
$\Sigma \vdash_{\mathsf{load}} q : \Gamma \binding \Sigma'$ (\figref{typing-module}); it mirrors loading at run time
(\secref{operational-semantics}). The \ruleName{module} rule types the body as a top-level statement, and
the \ruleName{predefined} rule gives a predefined module the signature of
Definition~\ref{def:predefined}.
Both import forms statically load their target, together with its containing modules
(\figref{typing-import-prefix}). A plain import \Replaced{statically loads the root and then each module
along the chain of names, recording each as a member of its parent}{also records each of these modules as a member of its
parent} (\Replaced{\ruleName{loads-as-cons}}{the static loads-as judgement}), so that the binding \Replaced{for the root}{created for the root of the target} gives attribute
access along the whole chain. A from-import also \Added{statically }loads any imported name that denotes a submodule\Added{, and the
names it imports must be distinct}. A
containing module of the target is exempt from \Replaced{static loading}{loading first} if it is the importing module or one of its
containing modules\Added{\speconly{ (\S\ref{aux:containing})}}, \Replaced{because at runtime it may still be loading when the import executes}{since at runtime it may still be loading}. The exemption applies only to from-imports, because
for a plain import
the only containing module that could never load first is the importing module itself, and an import naming a
module contained in the importing module is excluded outright\paperonly{ (\secref{no-load-dependent})}. \Replaced{Static loading is defined inductively, so a program with an import cycle is ill-formed.}{Loading a module
may thus require other modules to load first; the rules are interpreted inductively, so a program with an
import cycle is ill-formed, because a module in a cycle could finish loading only after itself.} Program
well-formedness (\figref{typing-module}) requires the main module to be well typed and hence,
recursively, every module that the program can load; a module that is never imported is not checked.
The rule \ruleName{module} types a module body under the context of $\mathcal{P}(\pyinline{builtins})$,
overridden by the imported context and then, as in \ruleName{def-body}, by an unbound entry for each name
declared in the body or bound by a pattern in it. The members of \pyinline{builtins} are thus in scope unqualified, and a name bound by the body
shadows a builtin throughout the module, so a use of the name before its declaration is rejected. Under mypy such a
use instead resolves to the builtin, following Python's run-time lookup. As with any scope, the names declared in the
module, including its imported names, must be distinct from one another and from any pattern variables in its
body. \Added{Since every module declares \pyinline{__name__} (\secref{modules-programs}), a module is ill-formed if its body
declares that name again, imports it, or binds it in a pattern.}

\input{spec/fig/typing-module}

The signature $\Gamma$ produced by static loading (\figref{typing-module}) comprises the classes\Added{, type aliases}
and variables defined by a module, together with its intrinsic \pyinline{__name__} and a stub for each submodule,
but not the names that it imports: following PEP 484\footnote{\url{https://peps.python.org/pep-0484/}}, an imported
name is a private dependency, not re-exported as part of the interface. Submodule stubs and the bindings of the module
body are disjoint, because the module rules exclude a module that binds a name that is also the name of
a submodule\paperonly{ (\secref{no-load-dependent})}.
