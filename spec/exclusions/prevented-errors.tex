A well-formed \PurePy program avoids the Python runtime errors listed in
\figref{prevented-errors}, under the conditions noted there. Typing also excludes the errors raised by
ill-typed operations, such as wrong operand types, calling a non-function, calling a function with the
wrong number of arguments, or attribute access on a value lacking the attribute\added{, and the statically excluded behaviours of \figref{coercions}, which are allowed by Python}. The semantics still gives each of these \replaced{cases}{errors } a termination kind and a rule (\specfigref{eval-fails})\added{, with $\errExcluded$ for a behaviour allowed by Python}, so that type soundness can be stated, as the conjecture that no run of a well-formed program aborts with \replaced{$\errType$, $\errAttr$, $\errName$ or $\errExcluded$}{one of these errors }.
