Result of matching pattern $p$ against value $v$ under environment $\rho$: the bindings of the pattern
variables if $p$ matches $v$, and $\noMatch$ if it does not. The result is $\errUndef$ for a numeric literal pattern if the equality of the literal and the value is undefined. \added{It is $\errType$ for a constructor pattern with more positional sub-patterns than the class has fields, or with two sub-patterns for one field, as in Python, and $\errExcluded$ for a list pattern against a tuple, a tuple pattern against a list, either against a range, and any constructor pattern which otherwise does not cover the fields of the class exactly, since typing rules these out and Python performs them without failing.} A Boolean literal pattern does not match a number, since Python compares the value with the literal by identity. Sub-patterns are matched left to right, their results composing with $\override$
(\secref{eval-patterns}).
