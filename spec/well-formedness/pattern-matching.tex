\subsubsection{Pattern checking}\label{sec:pattern-checking}

\input{spec/fig/pattern-matching/instance}
\input{spec/fig/pattern-matching/checking-pat}

A pattern must \emph{check} against the remaining type, $\Sigma; \Gamma \vdash p \checks \tau \binding \Delta$ (\figref{checking-pat}), before it is matched against the residual (\ruleName{match-case}). The bindings $\Delta$ give the types of the pattern variables. The judgement holds when every tuple pattern in $p$ is at a type which has no list or range values, every list pattern is at a type which has no tuple or range values, every dictionary pattern is at a dictionary type or at a type which has no dictionary values, every int literal pattern is at a type which has no float values, and every constructor pattern is at a type at which its class has an instance or with which its class is incomparable, as defined below. List, tuple, range, dictionary and float values are defined by subtyping:
\begin{defalign}
\tau \text{ has list values} & {}\iff \Sigma \vdash \tyList{\sigma} \subty \tau \text{ for some } \sigma \text{, or a disjunct of } \tau \text{ is a type variable} \\
\tau \text{ has tuple values} & {}\iff \Sigma \vdash \tyTuple{\seq{\sigma}} \subty \tau \text{ for some } \seq{\sigma} \text{, or a disjunct of } \tau \text{ is a type variable} \\
\tau \text{ has range values} & {}\iff \Sigma \vdash \clsRange[] \subty \tau \text{, or a disjunct of } \tau \text{ is a type variable} \\
\tau \text{ has dictionary values} & {}\iff \Sigma \vdash \tyDict{\sigma} \subty \tau \text{ for some } \sigma \text{, or a disjunct of } \tau \text{ is a type variable} \\
\tau \text{ has float values} & {}\iff \Sigma \vdash \tyFloat \subty \tau \text{, or a disjunct of } \tau \text{ is a type variable}
\end{defalign}
So list types, $\tySized$ and $\tyObject$ have list values; tuple types, $\tySized$ and $\tyObject$ have tuple values; $\clsRange[]$, $\tySized$ and $\tyObject$ have range values; dictionary types, $\tySized$ and $\tyObject$ have dictionary values; $\tyFloat$ and $\tyObject$ have float values; and a type variable, which may stand for any type, has all five kinds of value. The rules check a sub-pattern at the type of its position, a tuple component, list element, dictionary value or field, and a pattern at a union at each of its disjuncts. A variable pattern binds at the type at which it is checked, and a pattern named by \pyinline{as} is bound at $\matchedAs{\Sigma}(\Gamma, \tau, p)$; the bindings of sub-patterns compose by disjoint union, so a pattern that binds a name twice is ill-formed, and at a union the bindings of the disjuncts are joined. A pattern also checks against a type which has no disjunct of the form matched by the pattern: a tuple pattern when no disjunct is a tuple type of the pattern's length, a list pattern when no disjunct is a list type, a dictionary pattern when the type has no dictionary values, or a constructor pattern when its class is incomparable with the type (\ruleName{check-tuple-none}, \ruleName{check-list-none}, \ruleName{check-dict-none}, \ruleName{check-constr-none}). Such a pattern matches no shape of the type and binds its variables at $\tyNever$, the unit of the join; as with a variable pattern (\ruleName{check-var}), the variables must be unbound in $\Gamma$. At one disjunct of a union it therefore leaves the values of that disjunct to later cases, and a case with a pattern matching no shape at all is unreachable.

The conditions on tuple, list and int literal patterns ensure that pattern matching always has a result. Under the evaluation rules, matching a tuple pattern against a list or a list pattern against a tuple, or either against a range, or an int literal pattern against a float, aborts with $\errExcluded$ (\S\ref{aux:match}), although Python permits all of these. Tuple and list patterns therefore fail at $\tyList{\tyInt} \mathbin{|} \tyTuple{\tyInt, \tyInt}$, at $\tySized \mathbin{|} \tyTuple{\tyInt, \tyInt}$, at $\tyList{\tyInt} \mathbin{|} \clsRange[]$, and at a type variable. A dictionary pattern at $\tyObject$ or $\tySized$, which have dictionary values, is ill-formed, since the pattern may match a dictionary and yet its variables would be bound at $\tyNever$. The int literal pattern \pyinline{1} narrows to $\tyLiteral{1}$, but Python also matches the pattern against the float \pyinline{1.0}, which is not a value of $\tyLiteral{1}$. An int literal pattern at a type with float values is therefore ill-formed (\ruleName{check-literal}).

A constructor pattern cannot name $\clsRange$ (\ruleName{pat-constr}). Python rejects positional sub-patterns
for that class, and \PurePy excludes the keyword form as well, for uniformity. The condition on constructor patterns supplies the type arguments omitted by the pattern. The judgement $\Sigma \vdash C[\seq{\sigma}] \instanceAt \tau$ states that $C[\seq{\sigma}]$ is the \emph{instance} of $C$ at the type $\tau$ at which the pattern is checked. A pattern at a union is checked at each disjunct (\ruleName{check-union}), so an instance is never taken at a union. Below $C$ the base classes of $\tau$ determine the instance, which is unique because type arguments are invariant (\ruleName{instance-above}): at \pyinline{IntLeaf}, a subclass of \pyinline{Leaf[int]}, the instance of \pyinline{Leaf} is \pyinline{Leaf[int]}. Above $C$ the base arguments of $C$ determine the instance (\ruleName{instance-below}): at \pyinline{Tree[int]} the instance of \pyinline{Leaf} is \pyinline{Leaf[int]}, because \pyinline{Leaf[T]} extends \pyinline{Tree[T]}, but the instance of a class \pyinline{Node[T, U]} extending \pyinline{Tree[T]} is undefined, since \pyinline{U} does not occur in \pyinline{Tree[T]}. At \tyObject{} the instance of a class with type parameters is undefined, since every instantiation lies below \tyObject{} (\ruleName{instance-object}).

If the class $C$ of a constructor pattern is \emph{incomparable} with $\tau$, no value of type $\tau$ is an object
of $C$ or of a subclass of $C$, so the pattern binds its variables at \tyNever{} (\ruleName{check-constr-none}). A
class $C$ is incomparable with an instantiated class $D[\seq{\sigma}]$ if neither class is an ancestor of the other
(\ruleName{incomparable-unrelated}), or if the type arguments of the instantiation of $D$ above $C$ applied to its
type parameters are \emph{apart} from $\seq{\sigma}$, differing at some position outside type variables and unions, so that no
instantiation of the type parameters of $C$ makes the two equivalent (\ruleName{incomparable-below}). Constructor patterns are therefore ill-formed at type variables, which may stand for any type. Constructor patterns
naming classes with type parameters are also ill-formed at \tyObject{} and \tyNever. For example,
\pyinline{Node[int, str]} and \pyinline{Node[int, bool]} both lie below \pyinline{Tree[int]}, so a pattern naming
\pyinline{Node} is ill-formed at \pyinline{Tree[int]}.

\subsubsection{Shapes and shape typing}\label{sec:shapes}

\input{spec/fig/pattern-matching/shapes}

A shape $k$ (\figref{shapes})
denotes a set of values of its type $\shapeTy(k)$ (\S\ref{aux:shape-type}). The form $\shapeAny{\tau}{H}$ denotes the
values of type $\tau$ whose outermost head is not among those in $H$; the other forms are constructor,
tuple, list and dictionary shapes, each with shapes in place of sub-patterns. A list shape also records its
element type, which the element shapes do not determine. A constructor shape also carries an excluded
set: $\shapeAny{\patConstr{C[\seq{\tau}]}{\seq{k}}}{H}$ denotes the instances of $C[\seq{\tau}]$, or of any subclass not below a
class of $H$, whose fields, those of $C$, have shapes $\seq{k}$. A rest shape at a class type denotes
the same values as the constructor shape with a rest shape at each field, and is expanded into that
form only by splitting (\figref{split}): a class may refer to itself through its fields, so expanding
in advance would not terminate.

A head itself denotes a set of values: a literal its value, a class its instances, and $\headList{n}$
the lists of length $n$. Head typing $\Sigma \vdash h : \tau$ holds when the values of $h$ lie within
$\tau$. Shape typing $\Sigma \vdash k : \tau$ holds when $\shapeTy(k)$ is a subtype of $\tau$ and $k$ is
well-formed: each excluded head is typed at the type of the shape (at $\tyStr$, for the keys of a
dictionary shape) and each component shape at the type of that component.

The auxiliary function $\shapes{\Sigma}(\tau, H)$ (\S\ref{aux:shapes}) gives the shapes of $\tau$
once the heads in $H$ are excluded. A union contributes the shapes of its disjuncts and a dictionary type
the dictionary form; every other type contributes the single shape $\shapeAny{\tau}{H}$, or no shape at
all when $H$ exhausts $\tau$. The rest form therefore never carries a union or dictionary type, and
\ruleName{shape-rest} states this restriction as a side condition.

\subsubsection{Matching}\label{sec:matching}

\input{spec/fig/pattern-matching/typing-pat}

\emph{Matching} (\figref{typing-pat}) has three forms. The form on a single shape $k$ matches a pattern against that
shape, giving matched shapes $K$ and residual $L$. The form
on sequences matches the sub-patterns of a tuple, list, dictionary or constructor pattern against the
component shapes position by position. The form on
an ordered set of shapes $L$, used by the match rules, matches each shape of $L$ in turn. The pattern need not match every shape of $L$, so \ruleName{pat-shapes} takes the shapes of $L$
matched by the pattern, of which there must be at least one, and passes the unmatched shapes into the
residual untouched.

\input{spec/fig/pattern-matching/split}

A pattern matches a shape directly if the shape has the head tested by the pattern. Otherwise the shape
is first \emph{split} by the auxiliary judgement $\Sigma; \Gamma \vdash k, p \splits K, L$ (\figref{split}):
the shapes $K$ have the head tested by $p$, with the shapes of the component types drawn from $\shapes{\Sigma}$,
and the residual $L$ is the shape $k$ with that head excluded as well. The \ruleName{pat-split} rule matches
the pattern against $K$ and adds $L$ to the residual. Only the forms
with an excluded set split, and no head types at a tuple type, so the excluded set of a tuple shape is
empty and \ruleName{split-tuple} leaves the empty residual. Literal types do not include floats, so a float
literal pattern matches a rest shape directly (\ruleName{pat-literal-float}) rather than splitting it; the matched shape
is the whole shape, and the residual is the shape with the literal excluded. The matched shape therefore includes values
which are not equal to the literal. Those values are also in the residual, so the residual of an enclosing pattern is the
same as if the matched shape contained only the literal.
A constructor pattern whose class lies below a
class of the excluded set matches nothing, because an earlier case for the superclass has already
matched every instance. A constructor pattern matches the instance of its class at the type of the shape (\figref{instance}): a pattern \pyinline{Leaf(v)} at \pyinline{Tree[int]} matches \pyinline{Leaf[int]} and binds \pyinline{v} at \pyinline{int}.

A dictionary shape has a separate form,
$\shapeDict{\tau}{\beta}{H}$, standing for the dictionaries that hold each key $w$ in the domain of
$\beta$ with a value of shape $\beta(w)$, but that hold no key of $H$. A dictionary pattern takes its keys in order, with no key occurring twice. A key in
neither $\beta$ nor $H$ splits the shape at that key (\ruleName{split-dict}), adding to the residual the
dictionaries that lack the key; once every key of the pattern is in $\beta$ the keys match as a sequence
(\ruleName{pat-dict}), each key $w$ against $\beta(w)$. The empty dictionary pattern matches every
dictionary and leaves the empty residual.
