\section{Operational semantics}
\label{sec:operational-semantics}

\subsection{Values and environments}

Values, environments, outcomes and results are given in \figref{values}. A class value $\Type{C}$ is the
context entry of the class, and an object $\exObj{C}{\bind{\seq{x}}{\seq{v}}}$ records its class by name and fields in the order given by $\fields{\Sigma}(C)$. An opaque value $\opaqueVal{q.x}$ represents a predefined member by its
name alone, such as the class \pyinline{int} or decorator \pyinline{dataclass}. The value $\Unbound$
marks a variable of the current scope before its declaration is reached, which Python reports as an unbound
local. An environment binds a variable to $\Unbound$ wherever the corresponding context binds the variable to
the entry $\Unbound$, so that a shadowed binding of an enclosing scope is not visible. Throughout this section, $\Sigma$ is the class table produced by module checking of the program
(\secref{well-formedness-modules}) and, like $\mathcal{M}$ and $\mathcal{P}$, is ambient. For a statement $s$, \added{outcome $\outcome{\seq{v}}{\omega}$ represents $s$ printing the values $\seq{v}$, in order, and completing
as $\omega$. Completion}\deleted{the outcome}
$\assigns{\rho}$ represents $s$ \replaced{completing normally}{running to its end}, with accumulated environment $\rho$; \replaced{completion}{the outcome}
$\returns{v}$ represents $s$ returning the value $v$; and \replaced{completion}{the outcome} $\aborts{\kappa}$ represents the whole run
aborting, with termination kind $\kappa$.

\begin{specdefinition}{Composition of outcomes}
Composing statements sequentially composes their outcomes according to the following monoid, analogous
to sequential composition of static outcomes:
\begin{defalign}
\replaced{\outcome{\seq{v}}{\returns{v}} \override o}{\returns{v} \override o } & = \replaced{\outcome{\seq{v}}{\returns{v}}}{\returns{v} } \\
\replaced{\outcome{\seq{v}}{\aborts{\kappa}} \override o}{\aborts{\kappa} \override o } & = \replaced{\outcome{\seq{v}}{\aborts{\kappa}}}{\aborts{\kappa} } \\
\replaced{\outcome{\seq{v}}{\assigns{\rho}} \override \outcome{\seq{v}'}{\assigns{\rho'}}}{\assigns{\rho} \override \assigns{\rho'} } & = \replaced{\outcome{\seq{v} \concat \seq{v}'}{\assigns{\rho \override \rho'}}}{\assigns{\rho \override \rho'} } \\
\replaced{\outcome{\seq{v}}{\assigns{\rho}} \override \outcome{\seq{v}'}{\omega}}{\assigns{\rho} \override o } & = \replaced{\outcome{\seq{v} \concat \seq{v}'}{\omega}}{o } \quad (\text{otherwise})
\end{defalign}

\noindent with \replaced{outcomes of the form $\outcome{\seq{v}}{\returns{v}}$ or $\outcome{\seq{v}}{\aborts{\kappa}}$}{$\returns{v}$ and $\aborts{\kappa}$ } as left zeros, and $\replaced{\outcome{\varepsilon}{\assigns{\varnothing}}}{\assigns{\varnothing} }$ as left and right unit.
\end{specdefinition}

\replaced{\emph{Termination kinds} $\kappa$ record}{A \emph{termination kind} $\kappa$ records } how a run ends; all but $\errUndef$ and $\errExcluded$ are named after the exceptions raised by the same program
under Python in the same circumstances, except that $\errExit{0}$ also records a run which completes normally. A variable read before its assignment aborts with $\errName$ where
Python raises \pyinline{UnboundLocalError}, a subclass of \pyinline{NameError}; distinguishing the two would require
the environment to record whether unbound variables belong to functions or modules. Two termination kinds record operations which Python executes without an error. A run aborts with $\errUndef$ when it reaches a dynamically excluded operation, one which the type system cannot rule out
and \PurePy leaves undefined, such as a
comparison of two functions (\secref{no-coercions}). A run aborts with $\errExcluded$ when it reaches an operation
ruled out by the type system, such as a condition which evaluates to a non-Boolean.
Attribute references, dictionary keys and constructor patterns headed by a built-in class, when ruled out by the type
system, also abort with $\errExcluded$, even though Python sometimes rejects them; to be more precise here would require the
semantics to model the attributes Python assigns to a value, the keys which Python considers hashable, and whether a value
is an instance of an opaque class such as \pyinline{int} (\secref{eval-expressions}, \secref{eval-patterns}). A primitive
$\primVal{\primFn}$ is a predefined function whose meaning $\primFn$ is a function from
arguments to results (\specfigref{predefined-values}). Calling $\primVal{\primFn}$ with arguments $\seq{v}$ has result
$\primFn(\seq{v})$.

\replaced{Rule conclusions use a monadic let notation over results.}{The rules are given in a monadic metalanguage over results (\figref{values}). } If $r$ is
$\val{v}$, then $\mlet{v}{r}{\ldots}$ is the body with $v$ bound to that value; if $r$ is
$\aborts{\kappa}$, it is $\aborts{\kappa}$\added{ as a result, or $\outcome{\varepsilon}{\aborts{\kappa}}$ as an outcome}. The body is a result in the expression rules and an outcome in
the statement rules. A final
premise needs no propagation rule; earlier premises have one each, recording the subexpressions evaluated
before the failing one (\specfigref{eval-propagation}). The sequence \replaced{judgement uses }{and module judgements use }
results carrying a sequence of values\deleted{ or an environment} in place of a value.

\subsection{Expressions and statements}
\label{sec:eval-expressions}

A value is well-formed at a context entry, and an environment at a context (\specfigref{well-formed-values}).
For any context $\Gamma$, any $\bind{\rho}{\Gamma}$ and any statement $s$ with
$\Gamma \vdash s : R$, the statement evaluation judgement $\rho, s \Rightarrow o$ says that $s$ evaluates
to outcome $o$ in $\rho$ (\specfigrefTwo{eval-block-outcome}{eval-block-fails}). An \pyinline{if} or
\pyinline{assert} statement aborts with $\errExcluded$ when a condition evaluates to a non-Boolean\speconly{ (\ruleName{eval-if-nonbool}, \ruleName{eval-if-else-nonbool}, \ruleName{eval-assert-nonbool},
\ruleName{eval-assert-msg-nonbool})}, and a failing \pyinline{assert} statement also aborts with $\errExcluded$ when
its message is not a string\speconly{ (\ruleName{eval-assert-msg-nonstr})}. Top-level statements
are evaluated by a separate judgement, $q, \rho, t \Rightarrow o$ (\specfigref{eval-top-level}), mirroring the static
judgement (\specfigref{typing-top-level}): a sequence composes in the same way as a statement sequence, a mutual type region binds each of its names to $\typeEntry{\Gamma}(q, \seq{\chi}, i)$\speconly{ (\ruleName{eval-types})}, since
class and alias entries are also values, and a plain statement is evaluated by the statement judgement\speconly{
(\ruleName{eval-top-stmt})}. Function definitions delimit
the scope of sequential-composition effects, so as black boxes functions are always pure. The auxiliary function $\result$\speconly{ (\S\ref{aux:result})} reads the outcome of a statement as
the result of a call\speconly{; if the statement completes without returning, the result is $\val{\pyinline{None}}$.}\paperonly{:}
\paperinput{paper/operational-semantics/result}

For any context $\Gamma$, any $\bind{\rho}{\Gamma}$ and any expression $e$ with $\Gamma \vdash e \synth
\tau$, the expression evaluation judgement $\rho, e \Rightarrow r$ (\specfigrefTwo{eval-result}{eval-fails}) says that $e$ evaluates to
result $r$ in $\rho$, where $r$ is either $\val{v}$ or $\aborts{\kappa}$ (\figref{values}). A variable
not bound in $\rho$, or bound to $\Unbound$, aborts with $\errName$\speconly{ (\ruleName{eval-var-unknown},
\ruleName{eval-var-unbound})}. Function calls and constructor calls share one syntactic form, as do subscripting a container and applying a class to
type arguments; the semantics distinguishes them by the value of the callee or subject. A call whose
callee evaluates to a class is a constructor call, and a subscript expression whose subject evaluates to a class evaluates to the
class itself, since values carry no type arguments\speconly{ (\ruleName{eval-constr}, \ruleName{eval-class-type-args})}. A call of a value other than a closure, primitive or class, a call with the wrong number
of arguments, and a constructor call with arguments which do not cover the fields of the class, abort with
$\errType$\speconly{ (\ruleName{eval-call-nonfun}, \ruleName{eval-call-lambda-arity}, \ruleName{eval-call-def-arity},
\ruleName{eval-constr-arity})}, and a reference to an attribute absent from an object or a loaded module aborts with $\errAttr$\speconly{
(\ruleName{eval-attr-object-missing}, \ruleName{eval-attr-module-missing})}, as in Python. The operators
\pyinline{and} and \pyinline{or} evaluate their second operand only when the first leaves the result open, aborting with $\errExcluded$ if the first operand is
not a Boolean\speconly{ (\ruleName{eval-and-nonbool}, \ruleName{eval-or-nonbool})}, and
a conditional expression requires its condition to be a Boolean, like the
\pyinline{if} statement\speconly{ (\ruleName{eval-if})}, aborting with $\errExcluded$ otherwise\speconly{
(\ruleName{eval-cond-nonbool})}.

A comprehension evaluates its body once for each binding produced by its qualifiers, and
concatenates the results; a generator draws its bindings from the elements of a value, given by the auxiliary
function $\iterOp$\speconly{ (\S\ref{aux:iter})}: the elements of a
list, tuple, string or range, and the keys of a dictionary, as in Python. A generator over a
value other than a list, tuple, string, dictionary or range aborts with $\errType$\speconly{
(\ruleName{eval-qual-generator-nonseq})}, as in Python, and a guard aborts with $\errExcluded$ if it
evaluates to a non-Boolean\speconly{ (\ruleName{eval-qual-guard-nonbool})}.
Dictionary expressions and comprehensions with keys other than strings abort with
$\errExcluded$\speconly{ (\ruleName{eval-dict-nonstr}, \ruleName{eval-dict-comp-nonstr})}, as do subscripting and
membership with such a key; Python raises \pyinline{TypeError} only for keys it cannot hash, such as lists, but \PurePy
has no notion of hashing and cannot distinguish them from other keys.
Subscripting is given by the auxiliary function $\getitem$, and membership by
$\contains{\Sigma}$\speconly{ (\S\ref{aux:getitem}, \S\ref{aux:contains})}; both abort with $\errExcluded$ for a range, as does
subscripting for a Boolean index, which Python treats as the integer 0 or 1. An attribute reference on a
value other than a module or object aborts with $\errExcluded$\speconly{ (\ruleName{eval-attr-nonobject})}. In this version of \PurePy such values have no attributes, whereas in Python a string, for example, has methods; a reference rejected by Python with \pyinline{AttributeError} also aborts with $\errExcluded$, since \PurePy does not keep track of which attributes Python provides.

\subsection{Pattern matching}
\label{sec:eval-patterns}

A \pyinline{match} statement takes the first case whose pattern matches the value, running its body under
the bindings produced by the pattern, and does nothing if no case matches; the auxiliary function
$\dispatch$\speconly{ (\S\ref{aux:dispatch})} selects the matching case.
\paperinput{paper/operational-semantics/match}%
Whether a pattern matches is determined by the auxiliary function $\matchOp{\Sigma}(\rho, p, v)$\speconly{
(\S\ref{aux:match})}. A \emph{match result} $m$ is
$\matchOk{\rho'}$, a match, where $\rho'$ binds the variables of the pattern to the values that they matched;
$\noMatch$, a failure to match; or a termination kind $\kappa$, if matching aborts, such as $\errUndef$ for a numeric literal pattern if the equality of the literal and the value is undefined. When
matching aborts with $\kappa$ before any pattern matches, $\dispatch$ gives $\kappa$, and the run aborts with $\kappa$\speconly{ (\ruleName{eval-match-abort})}.
\speconly{Matching a list pattern against a tuple, a tuple pattern against a list, or either against a range
aborts with $\errExcluded$ (\S\ref{aux:match}); a constructor pattern against an object aborts with $\errType$ or
$\errExcluded$ when the sub-patterns do not cover the fields of the class (\S\ref{aux:match-fields}). A constructor pattern
whose head does not denote a class aborts with $\errName$, $\errAttr$ or $\errType$, as in Python, or with $\errExcluded$
for a predefined class such as \pyinline{int}, which Python matches by an instance test (\S\ref{aux:match}).}
\begin{specdefinition}{Composition of match results}
The match results of sub-patterns compose with
$\override$, matching sequentially, so that the first failure or abort determines the result:
\begin{defalign}
\matchOk{\rho} \override \matchOk{\rho'} & {}= \matchOk{(\rho \disjunion \rho')} \\
\matchOk{\rho} \override \noMatch = \noMatch \override m & {}= \noMatch \\
\matchOk{\rho} \override \kappa = \kappa \override m & {}= \kappa
\end{defalign}

\noindent with $\matchOk{\varnothing}$ as left and right unit.
\end{specdefinition}
\paperinput{paper/operational-semantics/pattern-list}%
A constructor pattern matches any object
whose class has the pattern's class among its ancestors, and its sub-patterns bind the fields of the
pattern's class\paperonly{:}\speconly{.}
\paperinput{paper/operational-semantics/pattern-constr}%
Since an object records its class by name, the class test of $\matchOp{\Sigma}$ is a comparison of
fully-qualified names.

\subsection{Modules and programs}

\begin{DeletedBlock}
\speconly{Module and program evaluation are given in \figref{eval-modules}; import evaluation in \figref{eval-import-prefix}; importing names from a loaded module in
\figref{eval-imports}.}\paperonly{Module and program evaluation are given in full in \specfigref{eval-modules}.}\speconly{ Context extension (\secref{well-formedness-modules}) applies to environments as well, with the same equations on values in place of context entries, except that a loaded module value $\modLoaded{q}{\rho}$ carries an environment whereas the context entry $\modLoaded{q}{\Gamma}$ carries a context.} \emph{Loading}, the judgement $q \Rightarrow_{\mathsf{mod}} r$, evaluates the import prefix
of $q$ and then its statement, mirroring module checking $\vdash_{\mathsf{mod}} q : \Gamma$
(\specfigref{typing-module}); as with the static rules, the mutual
recursion between loading and evaluation is grounded by program well-formedness, which rules out
import cycles (\secref{modules-programs}).
Loading takes a single module; an import loads the modules containing its target from the root down, each
before the module it contains, mirroring the static rules\speconly{, by the submodules judgement for a plain import and
as premises of the from-import rule}. If loading one of these modules aborts, the import aborts for the same reason and the modules after it are
not loaded.

Since
imports precede statements, every module that a statement can reference is loaded before the statement runs, and
loading is deterministic, so the semantics needs no cache
of loaded modules. Loading runs\speconly{ (\ruleName{eval-module})} a module body in $\mathcal{P}(\pyinline{builtins})$ overridden by
the environment of its imports, with each name declared in the body or bound by a pattern in it starting
unbound, mirroring the \ruleName{module} rule (\secref{well-formedness-modules}).
A program evaluates to a termination kind (\figref{values}): $\errExit{0}$ if the main module
loads, and otherwise the kind it aborted with. $\errExit{n}$ is a run that exited with status $n$\paperonly{:}\speconly{.}
\paperinput{paper/operational-semantics/program}%
An implementation must agree with the semantics on the termination kind of every run with defined behaviour; the form in
which the kind is reported is not prescribed.
\end{DeletedBlock}
\begin{AddedBlock}
\speconly{Module and program evaluation are given in \figref{eval-modules}.}\paperonly{Module and program evaluation
are given in full in \specfigref{eval-modules}.}\speconly{ Context extension (Definition~\ref{def:context-extension}) is extended
to environments, with the same equations on values in place of context entries, except that a loaded module
value $\modLoaded{q}{\rho}$ carries an environment whereas the context entry $\modLoaded{q}{\Gamma}$ carries a
context.} A program runs each module body once, after its imports have loaded, in \emph{load order}\speconly{ (\specref{aux:loads})}.
Load order is fixed by the imports alone, since imports precede statements and so cannot depend on the outcome of a
statement. The program rules thread the environments
$\mathcal{L}$ of the modules loaded so far, initially the environments $\mathcal{E}(\mathcal{A})$ of the predefined modules, given the
command-line arguments $\mathcal{A}$\speconly{ (\ruleName{eval-program} and \ruleName{eval-program-abort})}. The environment of a module is its
submodule stubs overridden by the environment assigned by its body, mirroring the \ruleName{module} rule
(\specfigref{typing-module}). Module bodies run in environments corresponding to the contexts in which those bodies are
checked\speconly{ (\ruleName{eval-module})}.

The output of a program is the concatenation of the values printed by its bodies. A program evaluates to its output
and a termination kind (\figref{values}): $\errExit{0}$ if every body runs to its end, and otherwise the kind of the
first body to abort, after whose output nothing more is printed. $\errExit{n}$ is a run that exited with status
$n$\paperonly{:}\speconly{.}
\paperinput{paper/operational-semantics/program}%
An implementation must agree with the semantics on the termination kind of every run with defined behaviour, and on
its output, each value written as by Python's \pyinline{str} followed by a newline; the form in which the kind is
reported is not prescribed.
\end{AddedBlock}
