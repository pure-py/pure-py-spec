\section{Operational semantics}
\label{sec:operational-semantics}

\subsection{Values and environments}

Values, environments, and evaluation results are given in \figref{values}. For a statement $s$, the result
$\assigns{\rho}$ represents \emph{normal completion} of $s$, with accumulated environment $\rho$; the result
$\returns{v}$ represents \emph{abrupt completion} of $s$, with return value $v$; and the result
$\aborts{\kappa}$ represents abrupt completion of the whole run, with termination kind $\kappa$.
Composing statements sequentially composes their results according to the following partial monoid, analogous
to sequential composition of result types:
\begin{defalign}
\assigns{\rho} \override \assigns{\rho'} & = \assigns{(\rho \override \rho')} \\
\assigns{\rho} \override \returns{v} & = \returns{v} \\
\assigns{\rho} \override \aborts{\kappa} & = \aborts{\kappa}
\end{defalign}

\noindent with $\assigns{\varnothing}$ as left and right unit.

\input{spec/fig/eval-values}

A \emph{termination
kind} $\kappa$ records how a run ends; all but $\errExit{n}$ are named after the exceptions the same program
raises under Python in the same circumstances. A primitive
$\primVal{\primFn}$ is a predefined function whose meaning $\primFn$ is a partial map from
arguments to outcomes (\figref{predefined}). Calling $\primVal{\primFn}$ with arguments $\seq{u}$ has outcome
$\primFn(\seq{u})$, and no derivation where $\primFn(\seq{u})$ is undefined.

The rules are given in a monadic metalanguage over outcomes (\figref{values}), in which
$\mlet{v}{o}{\ldots}$ binds the value of an outcome; for example, \ruleName{eval-binop} concludes
$\mlet{v'}{o}{\hat{\odot}(v, v')}$, which is $\hat{\odot}(v, v')$ where $o$ is $\val{v'}$, and
$\aborts{\kappa}$ where $o$ is $\aborts{\kappa}$. A final
premise needs no propagation rule; earlier premises have one each, recording which subexpressions succeeded
before the failing one was reached\speconly{ (\figref{eval-fails})}. The statement, sequence and module judgements use
outcomes of the same form, carrying a result, a sequence of values or an environment in place of a value.

\subsection{Pattern matching}

A \pyinline{match} statement takes the first case whose pattern matches the value, running its body under
the bindings the pattern produces, and does nothing if no case matches; the auxiliary function
$\dispatch$ (\paperonly{\figref{auxiliary-functions}}\speconly{\S\ref{aux:dispatch}}) selects the matching case.
\paperinput{paper/operational-semantics/match}%
Whether a pattern matches is determined by the pattern-matching judgement
$\rho, p, v \matches m$\speconly{ (\figref{eval-pat})}. A \emph{match result} $m$ is either $\matchOk{\rho'}$, a match, where $\rho'$ binds
the pattern's variables to the values they matched, or $\noMatch$, a failure to match. \speconly{Where a
pattern and a value are not comparable, as a list pattern against a tuple, there is no derivation and the
run has no result.} Sub-results compose with
$\override$, matching sequentially:
\begin{defalign}
\matchOk{\rho} \override \matchOk{\rho'} & {}= \matchOk{(\rho \disjunion \rho')} \\
m \override \noMatch = \noMatch \override m & {}= \noMatch
\end{defalign}

\noindent with $\matchOk{\varnothing}$ as left and right unit.
\paperinput{paper/operational-semantics/pattern-list}%
A constructor pattern matches any object
whose class has the pattern's class among its ancestors, and its sub-patterns bind the fields of the
pattern's class\paperonly{:}\speconly{.}
\paperinput{paper/operational-semantics/pattern-constr}%
An object records its class, whose qualified name is the identity of the class:
since a module declares each class name at most once, the class comparison in \ruleName{eval-pat-constr}
amounts to a comparison of qualified names.

\subsection{Statements and expressions}

Statement evaluation $\rho, t \Rightarrow r$ is given in \speconly{\figrefTwo{eval-block-outcome}{eval-block-fails}}\paperonly{full in \specification}. Both
judgements are indexed by a context $\Gamma$: they relate any environment $\rho$ of type $\Gamma$ and any
statement or expression well typed in $\Gamma$ to its result, and $\Gamma$ is the context recorded by the
closure, object and class values that evaluation forms (\figref{values}). Function definitions delimit
the scope of sequential-composition effects, so as black boxes functions are always pure. The auxiliary function $\outcome$\speconly{ (\S\ref{aux:outcome})} reads a statement's result as
the outcome of calling it\speconly{, $\val{\pyinline{None}}$ where the statement completes without returning.}\paperonly{:}
\paperinput{paper/operational-semantics/outcome}

Expression evaluation $\rho, e \Rightarrow o$\speconly{ (\figrefTwo{eval-outcome}{eval-outcome-ctd})} yields an
outcome, either $\val{v}$ or $\aborts{\kappa}$ (\figref{values}). The operators
\pyinline{and} and \pyinline{or} evaluate their second operand only when the first leaves the result open, and
a conditional expression requires its condition to be \pyinline{True} or \pyinline{False}, as
\ruleName{eval-if} does. A comprehension evaluates its body once for each binding its qualifiers produce, and
concatenates the results; a generator draws its bindings from the elements of a value, given by the auxiliary
function $\iterOp$ (\paperonly{\figref{auxiliary-functions}}\speconly{\S\ref{aux:iter}}): the elements of a
list, tuple or string, and the keys of a dictionary, as in Python. Subscripting, given by the auxiliary
function $\getitem$ (\paperonly{\figref{auxiliary-functions}}\speconly{\S\ref{aux:getitem}}), indexes a list, tuple or
string by an integer, counting from the end when negative, and a dictionary by a string key,
aborting with $\errIndex$, $\errKey$ or $\errType$ where Python raises the exception of that name; a
dictionary subscripted by a value other than a string is undefined. Likewise an attribute reference on a
value other than a module or object has no derivation: the attributes of built-in values are undefined.

\subsection{Modules and programs}

\speconly{Module and program evaluation are given in \figref{eval-modules}; import evaluation in \figref{eval-import-prefix}; importing names from a loaded module in
\figref{eval-imports}.}\paperonly{Module and program evaluation are given in full in \specification.}\speconly{ Context extension (\figref{context-ops}) applies to environments as well, with the same equations on values in place of context entries, except that a loaded module value $\modLoaded{q}{\rho}$ carries an environment where the context entry $\modLoaded{q}{\Gamma}$ carries a context.} \emph{Loading}, the judgement $q \Rightarrow_{\mathsf{load}} o$, evaluates the import prefix
of $q$ and then its statement, mirroring static loading $\vdash_{\mathsf{load}} q : \Gamma$
(\figref{well-formed-module}); as with the static rules, the mutual
recursion between loading and evaluation is grounded by program well-formedness, which rules out
import cycles (\secref{modules-programs}).
Loading takes a single module; an import loads the ancestors of its target from the root down, each
before its descendant, as in the static rules\speconly{, by the loads-as judgement for a plain import and
as premises of the from-import rule}.

Since
imports precede statements, every module a statement can reference is loaded before the statement runs, and
loading is deterministic, so the semantics needs no cache
of loaded modules. The rule \ruleName{eval-module} puts $\mathcal{P}(\pyinline{builtins})$ under a module
body's environment, mirroring \ruleName{wf-module} (\secref{well-formedness-modules})\paperonly{:}\speconly{.}
\paperinput{paper/operational-semantics/module}%
A program evaluates to a termination kind (\figref{values}): $\errExit{0}$ if the main module
loads, and otherwise the kind it aborted with. $\errExit{n}$ is a run that exited with status $n$\paperonly{:}\speconly{.}
\paperinput{paper/operational-semantics/program}%
An implementation must agree on which kind a run yields, although how it
reports one is not prescribed.
