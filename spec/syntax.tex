\section{Syntax}
\label{sec:syntax}

The syntax of \PurePy is given in \figrefThree{syntax-stmt}{syntax-expr}{syntax-types}. \figref{metavariables} summarises the metavariables used throughout.
A sequence $\seq{x}$ denotes $x_1, \ldots, x_n$ for some $n$; inside the brackets of a tuple, list, type
application or argument list it stands for the comma-separated elements, so $\exTuple{\seq{e}}$ is
$\exTuple{e_1, \ldots, e_n}$. The sequence $x \cons \seq{x}$ has head $x$ and tail $\seq{x}$, and
$\seq{x} \mathbin{\concat} \seq{y}$ is concatenation.
Comma-separated elements inside set braces are pairwise distinct, so $\set{x_1, \ldots, x_n}$ has $n$
elements; the set of the elements of a sequence, $\set{\seq{x}}$, assumes no distinctness. A sequence
comprehension $(x_i \mid i \in I)$, where the finite index set $I$ carries a total order, denotes the
sequence of the $x_i$ in that order. A judgement applied to sequences of equal length holds pointwise, so that
$\Gamma \vdash \seq{\psi} \synth \seq{\tau}$ abbreviates $\Gamma \vdash \psi_i \synth \tau_i$ for each $i$. When the order of its elements matters, a set $\set{x_1, \ldots, x_n}$ is
\emph{ordered} by position. A comprehension over an ordered set preserves the order of its source;
$X \setminus Y$ keeps the surviving elements of $X$ in their order; $X \disjunion Y$, defined when $X$
and $Y$ are disjoint, appends the elements of $Y$ to those of $X$; $X \cup Y$ appends the elements of
$Y$ not in $X$; and a product of ordered sets is ordered lexicographically.

\subsection{Lexical syntax}
\label{sec:lexical}

The grammar of \PurePy is an abstract syntax, and its metavariables range over values rather than
over source text: $n$ is a number and $w$ is a string, not the lexemes that denote them. A number is never
negative, since Python writes a negative number as unary minus applied to a literal, and a length or an
exit status is an integer. The translation of source text
into abstract syntax follows Python, including the indentation that delimits blocks. A list of type
parameters or type arguments is always present in the abstract syntax and may be empty. In source an empty
list is always omitted, along with its brackets, since Python's concrete syntax requires at least one element
between brackets; the empty tuple type, for example, is written \pyinline{tuple[()]}.

\subsection{Contexts}
\label{sec:contexts}

Metavariables $x$, $f$, $c$ and $\alpha$ range over \emph{variables}; idiomatically $f$ is used when the variable is expected to denote a function, $c$ when it is expected to denote a class, and $\alpha$ when it is a type parameter. A \emph{name} $q$ is a non-empty sequence of variables separated by dots (\figref{syntax-stmt}): a variable is a \emph{simple name}, and a name with at least one dot is \emph{qualified}. A name is \emph{fully qualified} when it is read from the root of the module hierarchy; modules (\secref{modules-programs}) and classes (Definition~\ref{def:class}) are identified by fully-qualified name.

\begin{definition}[Class]
\label{def:class}
A class $C$ is a fully-qualified name $\fq{q.c}$, written with a tilde: a module $q$ and a class name $c$ declared in $q$. A module
declares each class name at most once, so the fully-qualified name of a class is the identity of the
class. A class is also the type of its instances.
\end{definition}

\subsubsection{Context operations}
\label{sec:context-operations}

Contexts admit a non-commutative monoid of sequential composition $\Gamma \override \Delta$ (``override'') and
an idempotent commutative semigroup of parallel composition $\merge$ (``merge''). Together these form a
\emph{right near-semiring}~\cite{vanhoorn1967}: $\override$ right-distributes over $\merge$, but left
distributivity does not hold. Both are defined pointwise (\figref{context-ops}): override is right-biased
and has $\bot$ as both left and right unit, whereas merge has no unit, since a variable bound on one side
only is possibly unassigned.
\input{spec/fig/context-ops}

A third operation, \emph{context extension} $\Gamma \extend \Delta$ (also \figref{context-ops}),
combines module references for the same module recursively, preferring loaded references to stubs, and is
otherwise right-biased like override. It is used in processing an import prefix, in which two imports with the same root, such as
\pyinline{a.b} and \pyinline{a.c}, both bind the root and must combine rather than shadow.

\subsection{Expressions and statements}
\label{sec:expressions-statements}

Statements are sequenced by
juxtaposition, $s\;s'$; a function body, branch of a conditional and body of a case are statements.
A \emph{top-level statement} $t$ is a statement, class declaration or \pyinline{type} statement, also sequenced by juxtaposition; the body of a
module after its imports is a top-level statement, so class declarations and \pyinline{type} statements occur only at the top level of a
module. A \pyinline{type} statement declares a \emph{type alias}. Function definitions, class declarations and
\pyinline{type} statements bind \emph{type parameters} $\seq{\alpha}$, written in brackets after the name as in
Python 3.12. A \emph{mutual region} $d_1 \ldots d_{n+1}$ is a maximal contiguous block of \pyinline{def} statements: any other statement separates mutual
regions. Maximality is not enforced by the grammar in \figref{syntax-stmt}; the parser is responsible for
grouping consecutive \pyinline{def}s into a single mutual region. The well-formedness rules treat each
mutual region as one mutually-recursive binding\paperonly{ (see \secref{mutual-recursion})}.

An \emph{argument list} $a$ (\figref{syntax-expr}) is a sequence of positional arguments followed by
keyword arguments $x = u$, where an argument $u$ is an expression in a constructor call and a pattern in a
constructor pattern. A constructor call may also pass type arguments to the class; a constructor pattern
cannot, since Python does not permit type arguments in a class pattern. The auxiliary function $\fieldMap$
(\paperonly{\figref{auxiliary-functions}}\speconly{\S\ref{aux:field-map}}) pairs each field of the class
with an argument: the positional arguments fill the leading fields in order, and a keyword argument $x = u$
fills the field $x$. It is defined only if every field receives exactly one argument.

\paragraph{Type annotations.}

Parameters, returns and dataclass fields are annotated with type expressions $\psi$, and an assignment
may be annotated (\figref{syntax-types}). A dataclass specifies its base class by a type expression of the form $q[\seq{\psi}]$. A \emph{type} $\tau$ has the forms of a type expression, except that \Replaced{in place of a name applied to type arguments it has an \emph{instantiated class} $C[\seq{\tau}]$, a class applied to type arguments, written $C$ when there are none}{a class $C$ rather than a name is applied to type arguments, written $C$ when there are none}; the type system resolves a type expression to a type, expanding class names to classes and type aliases to types\speconly{ (\secref{types})}. \Added{The substitution $\subst{\seq{\tau}}{\seq{\alpha}}{\sigma}$ replaces each $\alpha_i$ in $\sigma$ by $\tau_i$, structurally, since a type binds no variables, and applies pointwise to a sequence of types or of bindings; it is defined only if $\seq{\tau}$ and $\seq{\alpha}$ have the same length. A \emph{type scheme} $\tyScheme{\seq{\alpha}}{\tau}$ binds type parameters $\seq{\alpha}$ in $\tau$; its \emph{instantiation} at $\seq{\sigma}$, written $\tyInst{(\tyScheme{\seq{\alpha}}{\tau})}{\seq{\sigma}}$, is $\subst{\seq{\sigma}}{\seq{\alpha}}{\tau}$, and $\tyScheme{\varepsilon}{\tau}$ is written $\tau$. The same binder is used over a sequence of bindings and over a set of types (\paperonly{\figref{auxiliary-functions}}\speconly{\S\ref{aux:fields}, \S\ref{aux:ancestors}}).} We write $\bind{\seq{x}}{\seq{\psi}}$ for the parameter list $\bind{x_1}{\psi_1}, \ldots,
\bind{x_n}{\psi_n}$.

\subsubsection{Operators}
\label{sec:syntax-operators}

The metavariable $\odot$ ranges over the supported binary operators other than \pyinline{and} and
\pyinline{or}, and $\ominus$ over the supported unary
operators, both enumerated in \figref{precedence}. The operators \pyinline{and} and \pyinline{or} are distinct
expression forms, since they need not evaluate both operands. The grammar of \figref{syntax-expr} is intentionally ambiguous
on operator forms; disambiguation is by the precedence and associativity given in \figref{precedence},
which follow Python.

\subsection{Modules and programs}
\label{sec:modules-programs}

A \PurePy \emph{program} is a finite map $\mathcal{M}$ from \emph{fully-qualified module names}
(\figref{syntax-stmt}) to \emph{module bodies} $\mu$, of which one is a distinguished \emph{main module} named
$\pymath{\_\_main\_\_}$; here $\nameOf(q)$ is the string literal naming $q$, so
$\nameOf(\pymath{\_\_main\_\_}) = \pymath{"\_\_main\_\_"}$. We identify a module with its fully-qualified name, writing ``module $q$'' for the module named $q$. A module body is a sequence of imports
$\seq{\iota}$, its \emph{import prefix}, followed by a top-level statement $t$; since imports are not statements, they can appear neither
within a statement nor after it. The statement begins with the
assignment $\exAssign{\pymath{\_\_name\_\_}}{\nameOf(q)}$, which binds the name of the module when the module
loads (\secref{well-formedness-modules}).

A second map $\mathcal{P}$ gives the
predefined modules of \figref{predefined-values}, which have no body: $\mathcal{P}$ takes each such name to its
environment and context (Definition~\ref{def:predefined}). The two domains are disjoint, and their union is
prefix-closed: the parent of any module in $\dom(\mathcal{M}) \cup \dom(\mathcal{P})$ is itself in
$\dom(\mathcal{M}) \cup \dom(\mathcal{P})$.\footnote{A source tree encodes such an $\mathcal{M}$: its modules are the \texttt{.py} files and the
directories, each named by its path, so the domain is prefix-closed by construction. The statement of a module is
the statement sequence of its \texttt{.py} file, or of its \texttt{\_\_init\_\_.py} for a directory, preceded by the
$\pymath{\_\_name\_\_}$ assignment; a directory without an \texttt{\_\_init\_\_.py} (a namespace package,
PEP 420, \url{https://peps.python.org/pep-0420/}) contributes that assignment alone.} The maps $\mathcal{M}$ and $\mathcal{P}$ are fixed and ambient in all
definitions that follow.

\begin{definition}[Predefined contexts and environments]
\label{def:predefined}
$\mathcal{P}$ takes each module $q$ of \figref{predefined-values} to a pair $(\Gamma, \rho)$, where $\Gamma$
binds $\pymath{\_\_name\_\_}$ at $\tyStr$ and each member of $q$ at the context entry listed in \figref{predefined-signatures}, and $\rho$ binds $\pymath{\_\_name\_\_}$ to $\nameOf(q)$ and each member to the corresponding value
(\figref{predefined-values}). These signatures name types
that are themselves members, sometimes of another predefined module, so each is well-formed in the union of
the predefined signatures.
\end{definition}
